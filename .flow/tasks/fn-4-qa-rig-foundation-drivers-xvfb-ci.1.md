## Done summary
Built the QA rig foundation. dettivo-qa now has a driver interface (launch, snapshot, find, wait_for_label, click, type_text, read_value, screenshot, close) with two implementations: cua-driver through a private `cua-driver serve` socket and `cua-driver call` per action (static labels read from the markdown tree since cua indexes only actionable elements, screenshots from screenshot_png_b64), and an in-repo fallback over the atspi crate (accessibility bus, per-app tree walk with pid matched through the bus's connection credentials) plus x11rb (XTEST clicks and typing through the keyboard mapping, GetImage screenshots, _NET_WM_PID window lookup). Every scenario runs in an isolated profile (own HOME, XDG config/state/data under a short /tmp root, the daemon socket isolated through DETTIVO_IPC_SOCKET, XDG_RUNTIME_DIR inherited on purpose so the session bus, the accessibility bus, the display and PipeWire stay reachable, the model directory linked in) whose leak check names processes still alive and sockets left under the root. Evidence lands under qa-evidence/<run>/<scenario>.<driver>/ as screenshot.png, tree.json and receipt.json (scenario, driver, outcome, reason, evidence, timings, duration). The contract replay sends every fixture to a fresh daemon with the README's tolerant matching and reports pass, fail, skip (capability flag not declared, never counted as passed) and pending (NOT_IMPLEMENTED for a method whose spec has not landed; a failure under --strict). The virtual audio check builds a fixture, plays it into a PipeWire null sink through scripts/qa/audio-rig.sh, records the sink's monitor with pw-record (stream.capture.sink), correlates the recording with the fixture over a lag search, and proves an unload mid-recording is visible to the recorder (the monitor source vanishes and the samples after the unload are silent); without PipeWire it reports skipped. lint-scenarios refuses a scenario file that names a driver implementation; doctor names the missing display, session bus, accessibility bus or tool.

QA mode inside the product: dettivo_core::qa parses the macOS-compatible variables (DETTIVO_QA_MODE with the DETTIVO_QA and DETTIVO_MOCK_MODE switches, QA_ALLOW_RELEASE, MOCK_MIC/SYSTEM_AUDIO/INSERT/INPUT/A11Y/LLM/ENGINE, FORCE_CPU, MODEL_SERVER, E2E_COMPLETE/STEP/SEED/OPEN/ROUTE), validates values, requires QA mode for any hook, refuses QA mode in a release build unless allowed, and rejects an unknown name under a reserved prefix by name; dettivod exits 2 printing the variable, and the Qt hosts do the same through qt/host/qa_environment.cpp before any GUI object exists. docs/qa.md is the table both parsers are tested against.

CI gains the drive job (Xvfb, session bus, accessibility bus and openbox through scripts/qa/xvfb-session.sh; cua-driver installed at the pinned 0.20.0 through scripts/qa/install-cua-driver.sh; contract replay; scenario, release-text and accessible-name lints; the placeholder drive on both drivers; the audio check; evidence uploaded as an artifact) and a weekly qa-weekly workflow running the whole pack on the fallback driver. just qa, qa-contract, qa-drive <scenario> [driver], qa-drive-all, qa-drive-cua, qa-audio, lint-scenarios, lint-release-text and lint-a11y-names are the recipes, mirrored in the Makefile.

Baseline: none (the spec defined no Quick commands). Verify: just build test lint exit 0; just qa on the development machine (contract 25 passed, 0 failed, 1 skipped, 54 pending; placeholder_window pass on atspi and cua; audio-check pass with correlation 1.000 and unload detected).

Coverage: R1 the placeholder_window scenario passes on both drivers locally and in the CI drive job under Xvfb, writing screenshot.png, tree.json and receipt.json; doctor and the xvfb-session script name a missing display, session bus or accessibility bus; R2 the Driver trait is the only surface a scenario sees, lint-scenarios (unit-tested against the shipped pack and a planted violation) fails on a driver mention, the weekly workflow runs the pack on the fallback driver; R3 profile::tests prove isolation, the model link and the leak check naming a live process and a leftover socket, and the runner fails a scenario that leaks; R4 audio::check on the real PipeWire session (correlation 1.000, unload detected) with the fixture and correlation unit-tested, the rig script naming module-null-sink on failure; R5 qa::tests and qa_environment_test cover every documented variable, bad values and unknown names by name, release refusal, and the docs table; qa_env.rs proves the daemon exits 2 naming the variable and logs QA mode on; the <host>-qa-refusal CTest proves each Qt host refuses by name; R6 replay::run with per-method pass/fail/skip/pending, unit-tested normalisation and flag checks, run in CI by just qa-contract; R7 scripts/lint-release-text.sh, scripts/lint-accessible-names.sh and just test-qt run in the drive and unit-qml jobs and name the offender.

Notes for the conductor: the cua driver needs cua-driver's markdown tree for static text; if a later cua release indexes labels, the fallback parser simply stops adding rows. PipeWire keeps a capture stream alive on an unloaded sink and feeds silence, so unload detection is the vanished source plus the silent tail rather than a recorder exit. The screenshot PNG is written uncompressed (no image crate) and is large on a HiDPI display; the visual regression spec can switch it to a compressed encoder when it adds comparisons.
