## Done summary
fn-31 ships the packaging and release path for Dettivo for Linux on top of the previous worker's scaffolding (Cargo metadata, `dettivo completions` and `--version` with the commit, the engine discovery order with `speech.engines[].directory`, `NOTICE.md` with the `lint-notice` xtask, the icons, the preset, the manifest and the first `package.sh`). The scaffolding compiled and its tests passed as found; the first commit only applied rustfmt to it.

R1, the release tree: `scripts/package.sh` (`just package [dist]`) builds every crate in release mode with the three engines on Vulkan, installs the Qt binaries and the module through CMake with `/usr` as the prefix, adds the units, the preset, the desktop entry, the icons, the completions from the shipped binary, the licence and `NOTICE.md`, checks the tree against `packaging/manifest.txt` and writes the `.tar.zst` with `SHA256SUMS`. `check-manifest.sh` gained the `--files` mode for a `pacman -Ql` list and the `--update` mode the manifest header already promised, and `test-check-manifest.sh` proves it names a missing path, an extra path and a shipped model. The render check found that every installed Qt binary carried a runtime path naming only the `Dettivo` module directory while linking `libDettivoStyle.so`, so `dettivo-app` could not start from a real install; `DETTIVO_INSTALL_RPATH` in `qt/CMakeLists.txt` now names both module directories for the hosts and the style library carries the `Dettivo` directory. The desktop entry's categories now validate. On this machine the packaged Whisper engine reports `vulkan` and every engine reports `cpu` under `DETTIVO_FORCE_CPU=1`.

R2, the recipes and the install test: `packaging/aur/dettivo-bin` (the release tarball verified against the published `SHA256SUMS` in `prepare()`) and `packaging/aur/dettivo` (the tagged source through `just package` inside `build()`, the manifest check in `check()`), each with `.SRCINFO` and the shared install message. `scripts/packaging/build-package.sh bin|source` copies a recipe to `build/aur/`, drops the local tarball or a `git archive` beside it, runs `makepkg` (as a `builder` user when root), and runs `namcap` when installed, failing on its errors. `scripts/packaging/install-test.sh` installs with `pacman -U` or unpacks under `--root`, then checks the file list against the manifest, `desktop-file-validate`, `systemd-analyze verify`, `dettivo --version`, the three completion scripts loading in bash, zsh (`compinit` exits 0) and fish, Home rendered from the installed module on the offscreen platform, every engine's help, the CPU-fallback smoke over whisper, parakeet and llm on tiny.en, parakeet-v2 and qwen3-1.7b, and one dictation of the fixture through the installed daemon with the mock microphone, timing the completion event against NFR-2 and reading `dettivo doctor --json` for the tier and the per-engine backend; `install-test.json` names each step with outcome, detail and exit code. `scripts/packaging/lint.sh` (`just lint-packaging`, part of `just lint`) runs shellcheck when present, the manifest self-test, the `pkgver` and `.SRCINFO` checks, the install-script identity, the desktop entry and the changelog section. `ci.yml` gains `package` (tree, bin recipe, namcap, artifacts), `package-source` (the source recipe) and `install` (a clean container after `pacman -U`, the cached test models, the whole install test, the report uploaded), and the `lint` job runs `lint-notice` and `lint-packaging` with shellcheck installed.

R3, the release: `.github/workflows/release.yml` runs on `v*` tags and on dispatch with `dry_run` defaulting to true. `prepare` checks the tag against `Cargo.toml` and extracts the version's section from the new `CHANGELOG.md` with `scripts/packaging/release-notes.sh`, failing before any build on a mismatch or a missing section; `build` runs `just build test lint` and `just package package-bin`; `install` runs the install test on a second clean container; `publish`, only on a tag, creates the release with the tarball, `SHA256SUMS` and the notes, downloads them again and checks the sums. A dry run leaves the three files as workflow artifacts. `packaging/aur/publish.sh` pushes both recipes to the AUR by hand, refuses to run in CI and needs `DETTIVO_AUR_PUBLISH=1`.

R4, the session arm: `install-test.sh --session` (after a system install) reloads the user manager, enables `dettivod.socket`, times `dettivo status ping` against the 300 ms budget with the service stopped, runs `dettivo setup omarchy` when the CLI offers it or the Hyprland arm otherwise, and starts `dettivo-osd.service`, passing on a running unit or an exit 0 with the panel notice. The mock-microphone dictation runs in every mode, so the CPU-tier take is measured under a prefix too. `dettivo-qa pack release` is the dictation pack plus `contract_strict` (the fixture replay against a fresh daemon with pending methods failing, filed as `contract-replay.json`) and `packaging`, which reads `install-test.json` from `DETTIVO_INSTALL_TEST_REPORT` or `build/install-test.json` and fails naming every check that did not pass.

R5, the notice and the completions: `NOTICE.md` names the engines and their ggml, Qt, layer-shell-qt, tomlplusplus, the font, the ported macOS code and every crate in `Cargo.lock` in a generated table; `just lint-notice` now runs in `just lint`. A `dettivo-cli` test proves the three completion scripts name the subcommands and that `--version` prints the version and the commit, and the install test loads them in the real shells.

R6, the docs: `docs/install.md` covers the AUR packages, what lands where, the engine discovery order and building the package; `docs/RELEASING.md` documents the whole gate as five named steps (the dictation pack, the benchmark, the strict contract replay, the packaging step, the changelog and the tag); `docs/config.md`, `docs/engines.md`, `docs/qa.md`, `docs/api/linux-deltas.md` and the README table are updated; ADR 0034 records the install layout, the reserved CUDA drop-in, the recipes and the release workflow.

Verified on this machine: `make build test lint` under the gate lock is green at the final commit; `scripts/package.sh dist` with unpacked Vulkan-Headers and SPIRV-Headers through `CMAKE_PREFIX_PATH` produced the tree, the manifest check passed (116 files), the Whisper engine from the tree reported `vulkan` and `cpu` under `DETTIVO_FORCE_CPU=1`; `build-package.sh bin dist` and `build-package.sh source` (a full release build inside `makepkg` with a scratch `just`) both produced packages whose `pacman -Qlp` lists match the manifest; `install-test.sh --root` against the bin package passed every step (fish skipped, not installed here), with the fixture dictated on the CPU tier in 264 ms of transcription and the doctor naming `cpu` with `DETTIVO_FORCE_CPU=1`; shellcheck 0.11 from a scratch binary is clean over the packaging scripts.

Deliberately left out: no `dettivo-engines-cuda`, AppImage, Flatpak or Snap; no AUR publish from CI. Not verified here: `namcap` (not installed on this machine, no root; CI runs it and `build-package.sh` fails on its errors), the CI container runs of the `package`, `package-source` and `install` jobs and the `release.yml` dry run (they need a push), and the `--session` arm (it requires a system install and real user units, which this desktop must not receive; it runs on the release VM). The `.SRCINFO` sums are `SKIP` until `publish.sh` pins them at the first release.
