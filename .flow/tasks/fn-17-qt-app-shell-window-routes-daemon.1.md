### Summary
Built the desktop app. `dettivo-app` is a thin C++ host (qt/apps/dettivo-app/app_main.cpp, host pieces under qt/host/app/) around the shared module's new screens under qt/qml/Dettivo/app/: `AppWindow` (compositor-native chrome, the page the router names, Super+F fullscreen, Escape closes a detail or fullscreen, `/` goes to History), `Sidebar` with `SidebarItem` and the three `SidebarFooterRow`s (speech engine, language model, socket mode), `PageHeader`, `HomeRoute` built to home.png (the status sentence with the real hold and toggle chords and the focused app from `config.get` and `insert.target`, `InstrumentStrip` with the mode `SegmentedControl` bound to `dictation.mode` through `config.set`, the input from `audio.devices`, the `Waveform` fed by `audio.level`, Start dictation and Start meeting, `TodayList` over the newest day of `transcripts.list` in tabular numerals, `RightRail` with the four engines from `speech.engines`, `speech.selection.get`, `engine.state`, `job.progress` and `model.download` with the 2 px progress hairline, and the agent surfaces from `system.capabilities`), `DaemonBanner` (the daemon-unavailable state with the systemd hint, shown after a 1.5 s grace and cleared on the first answer), `EmptyState` (sentence, reason, key or button, the urgent square), `RouteScaffold` and the scaffolds `HistoryRoute` (the store by day or the designed empty state; the detail's state sentence), `MeetingsRoute` (list, live, detail with their designed states), `SettingsRoute` (eight sections as tabs, each naming the config.toml keys it writes) and `OnboardingRoute`. Every colour, size, spacing and motion value is a Theme or Motion token; the frame's sizes are new tokens (sidebarWidth, pagePaddingX/Y, rightRailWidth, instrumentStripHeight, appWindowWidth/Height, progressHairlineWidth).

Host: `Router` (the 17 names `onboarding`, `home`, `history`, `history.detail`, `meetings`, `meetings.live`, `meetings.detail`, `settings`, `settings.<8 sections>`, `agents`; titles; a history stack; `parse` refuses anything else naming the routes), `StatusModel`, `EnginesModel`, `HistoryModel` + `NewestDayModel` (keyset paging with the daemon's cursor), `ConfigBinding` (effective value and source, `set` through the daemon), `AppState` (`$XDG_STATE_HOME/dettivo/state.toml`: window geometry, last route, first-run progress), `AppControl` (`app.sock` beside the daemon socket: `raise`, `open`, `status`; a second `dettivo-app` forwards and exits 0 before any QGuiApplication exists), `AppJournal` (`$XDG_STATE_HOME/dettivo/qa/app.jsonl` under QA mode: `first_frame` with application/qml phases, `theme_applied` with the ms and accent, `idle`), `sample_data` (the baseline's facts for `--render <png> --sample`).
