## Done summary
Built the REST shim. dettivo-rest (new crate) is a hand-rolled HTTP/1.1 server over tokio and httparse (already in the tree through reqwest; no framework crate): a request head capped at 16 KiB, a body of exactly Content-Length bytes up to [rest] max_body_bytes (a longer declaration is answered 413 before the body is read and the connection closes), keep-alive with pipelined bytes carried into the next request, a per-request timeout, and the route handler run off the runtime's workers. auth reads Authorization: Bearer or X-Dettivo-Token and compares in constant time with the token resolved in the macOS order (DETTIVO_IPC_TOKEN, the Secret Service item, the 0600 token file), which now lives in dettivo_core::token and is shared with the daemon's peer_token mode; a missing or wrong token, and a Host header that is not loopback, answer 401 with the contract's UNAUTHORIZED_CLIENT body and the macOS messages. routes maps /v1/{namespace}/{method} onto namespace.method for GET and POST, coerces query values the macOS way (true/false, integers, comma lists) and overlays a JSON object body, consults the catalog so an unknown route is 404 NOT_FOUND and a reserved method reaches the daemon's NOT_IMPLEMENTED as 501, and answers /v1/events/subscribe 501 naming the socket and MCP. stream runs POST /v1/transcripts/import/stream through transfer.begin/chunk/commit into transcripts.import (filename from the query, then X-Dettivo-Filename, then the content type; target_kind, mode and language defaulted; the macOS cancel reasons on failure) and GET /v1/transcripts/export/stream through transfer.begin, transcripts.export (id, or the Linux scope/from/to), transfer.pull and transfer.commit with the export's Content-Type and an attachment filename. status is the contract's app_code to HTTP map with the JSON-RPC error object under error. backend is a trait: SocketBackend (one Unix socket connection per request, APP_NOT_RUNNING 503 with the systemd hint when the daemon is gone) or the daemon's own router.

Hosting: crates/dettivod/src/rest.rs starts the listener beside the socket when [rest] enabled = true, with the token resolved at start (no token: no listener, the three sources logged) and every route calling router::call in-process (the dispatch body, now shared with the socket path); system.capabilities.rest reports enabled, port (the ephemeral one when port = 0) and bind. dettivo rest serve [--port] [--bind] hosts the same server as a process over the socket with the token from --token/--token-file or the macOS order; dettivo rest status reports host, listener and authorisation and exits 2 with no listener; dettivo rest token prints the source and never the token; dettivo doctor prints the rest row. [rest] (enabled, port, bind, max_body_bytes, request_timeout_ms) joins the schema (rest_schema.rs), the default file, docs/config.md and the print_default fixture; a bind outside loopback fails config.validate naming rest.bind and the daemon runs on defaults with no listener. A second server on the port fails naming the port and dettivo rest status.

Fixtures and QA: crates/dettivo-rest/fixtures/{routes,auth,errors,stream,vscode}/ hold one request and answer per file (55 fixtures), replayed by the crate's harness against a live seeded daemon: the crate's tests/harness.rs runs them against the daemon-hosted shim and against a process-hosted shim over the socket; dettivo-qa rest (just qa-rest, make qa-rest) starts a seeded daemon with the shim on an ephemeral port and a known token; dettivo-qa contract carries the same section and levels the rest capability block as it does hotkeys; CI's drive job runs qa-rest. The macOS VS Code extension does not call the shim (it syncs the editor context to a file and runs voice-navigation commands), so the vscode/ set carries the request shapes the macOS REST tests exercise for an IDE bridge (health, latest, one transcript, insert, dictation status, stop, export stream); ADR 0028 and docs/rest.md record that, with the manual desktop smoke documented.
