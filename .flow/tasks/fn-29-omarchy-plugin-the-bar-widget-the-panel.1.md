## Done summary
On Omarchy, Dettivo now lives in the bar. The shared module gained `Dettivo.BarGlyph` (the 16 px six-bar mark with five states, the meeting timer and a dimmed hint) and `Dettivo.BarPanel` (the 340 px panel from `omarchy-bar-panel.png`: state header with the REC chip, the mode segment, Dictate and the meeting action, the engine, Enhanced and insertion rows, the recent list and Open Dettivo with its shortcut; `unavailable` and `hint` are states of the same item), with `tst_bar.qml` covering every state, row, action, signal and accessible name. A new Qt host, `dettivo-bar`, renders both outside Quickshell for the visual job under `DETTIVO_E2E_BAR_STATE`.

The plugin is the folder `omarchy/` in this repository: a manifest with schema 1, id `gmickel.dettivo`, kinds `bar-widget` and `panel`, `keepLoaded`, category Developer Tools, the three settings entries and `omarchy.minDettivo`; `BarWidget.qml`, `PanelPopup.qml` and `Panel.qml` as a thin wiring layer over `DettivoState.qml`, a Quickshell singleton around one `dettivo --json events --follow` process and one short `dettivo --json` call per fact and action (`DettivoFacts.qml`). The three files that touch the module import it as a directory from `/usr/share/dettivo/qml/Dettivo` (verified to load the module's plugin library inside a foreign Quickshell instance) and sit behind Loaders that stay inactive until the module is known to exist, so a missing module shows a dimmed glyph and the install hint instead of a QML error; an old daemon shows the upgrade hint. The `panel` kind hosts `Dettivo.Osd` on a `PanelWindow` at the `[osd]` position and holds `dev.dettivo.OmarchyPanel` through the new `dettivo osd host-panel` verb while `[omarchy] osd = "panel"`; `dettivo osd status` now answers from the disabled notice when no pill process runs. `scripts/omarchy/export-plugin.sh` writes the folder into a checkout of the `omarchy-dettivo` mirror byte for byte, and `scripts/package.sh` installs it at `/usr/share/dettivo/omarchy`.

R1: `scripts/lint-omarchy-plugin.sh` joined `just lint` (and the Makefile) as `lint-omarchy`: the manifest fields, `omarchy plugin validate` where the shell is installed (it passes on this Omarchy 4 desktop), the manifest version against `Cargo.toml`, the `minDettivo` pair, no symlinks, and every plugin QML file through `qmllint --bare` and `qmlformat` against the shell shim. The manifest fields are also a unit test in `crates/dettivo-cli/src/omarchy.rs`. The export script was run into a scratch git checkout: the result diffs clean against `omarchy/` and validates. R2: `tst_bar.qml` and the plugin tests `tst_plugin_hints.qml` and `tst_plugin_events.qml` (run by CTest as `dettivo-omarchy-plugin-test` through `scripts/qa/omarchy-plugin-test.sh`, which stages the plugin against the build tree and runs it under `qt/fixtures/omarchy-shell/`, a pure-QML stand-in for `qs.Commons`, `qs.Ui`, `Quickshell` and `Quickshell.Io` whose Process shim the tests answer by hand); `dettivo-bar` carries the render and negative style-check CTest cases. R3: the `omarchy_bar` drive asserts the daemon's state through `dettivo dictation status --json` before, during and after a CLI-started take and captures the bar's right section with `grim` at each step, comparing the crops with `dettivo-visual-diff`; it runs only where the shell has the plugin enabled and `DETTIVO_QA_OMARCHY_LIVE=1` allows a drive against the live daemon, and on this machine it reported the skip reason (the plugin is not enabled in the user's shell, which this task was told not to touch). R4: the `omarchy_osd_host` drive passes on this machine: with `osd = "panel"` the claimer holds the name, `dettivo-osd` exits naming it, `dettivo osd status` reports `host = "disabled"` with the notice and no control socket exists; with `osd = "service"` the claimer exits 0 without claiming and `dettivo-osd` shows one listening pill. R5: `dettivo setup omarchy [--check] [--stdout] [--no-plugin] [--git <url>]` enables `dettivod.socket`, writes the Hyprland Lua snippet, copies the plugin into `~/.config/omarchy/plugins/gmickel.dettivo/` (or adds the mirror through `omarchy plugin add`), rescans and enables it, then `hyprctl reload` and the shell rescan, each step reported as `ok`, `written`, `skipped` (with the reason, including the missing `omarchy` command) or `failed` naming the command and its exit code; `--check` reports every step as JSON, `dettivo doctor` gained an `omarchy` line, and the integration test covers `--stdout`, `--git`, `--no-plugin`, `--check` and the doctor line against a profile daemon. The version-skew cases (an old `system.version`, the module path absent) are the plugin tests. R6: `panel` (idle, recording, transcribing, meeting, hint) and `bar-glyph` (five states) joined `qa/visual/manifest.toml`; the panel's crops come from the panel box of `omarchy-bar-panel.png` and the glyph's from the strip at the foot of `osd.png`; `dettivo-qa visual` passes all 100 entries, with the Black Gold crop gating the meeting panel and every glyph state and approved renders recorded in `docs/design/baselines.md` for the rest. R7: `docs/omarchy.md`, the `[omarchy]` section of `docs/config.md` (`glyph`, `level_meter`, `osd`, `history_items`, `open_shortcut`, all in the schema, the default TOML and the `print_default` fixture), `omarchy/README.md`, ADR 0030 in the index, plus the design README, the OSD, hotkeys, daemon, QA and accessible-names docs.

Verified with `make build test lint` green at the final commit (the justfile's twin; `just` is not installed here), `cargo run -q -p dettivo-qa -- contract` (the print_default fixture regenerated for the new section), `cargo run -q -p dettivo-qa -- visual --surface panel` and `--surface bar-glyph`, `cargo run -q -p dettivo-qa -- drive omarchy_osd_host` (pass) and `drive omarchy_bar` (skip with its reason), `scripts/lint-omarchy-plugin.sh build/qt`, `scripts/qa/omarchy-plugin-test.sh build/qt`, `omarchy plugin validate omarchy/`, and the export script against a scratch checkout.

Left out on purpose: the full `dettivo setup omarchy` run and the `omarchy_bar` drive were not executed against this desktop's real shell, systemd units or daemon, because the task forbade changing the user's Omarchy configuration and plugins; both are exercised to the edge of that boundary (`--stdout`, `--check`, the copy step's unit test, the drive's preflight). The plugin's panel reads the shell's `Color` and `Style` only for the bar chrome it draws itself (the button, the hint text); the panel and the pill resolve their palette from the same Omarchy theme files through the module's `Theme`, so no second binding of the shell singletons onto the module was added. Meeting start and stop go through `dettivo call meetings.start|stop` because the CLI has no `meetings` verb on `main` yet; the timer follows `meeting.state`'s `live_last_end_ms`. The AUR package, the release workflow and the mirror repository's own automation stay with S-31.
