## Done summary
Built the microphone capture layer. dettivo-audio connects to PipeWire on a dedicated thread (the PipeWire proxies are single-threaded) and exposes Send handles: AudioService with the graph snapshot (every Audio/Source and Audio/Sink node with name and description, plus default.audio.source read from the "default" metadata object and watched for changes) and CaptureHandle for a running capture. A capture requests s16 mono at 16 kHz from PipeWire (no resampler in the daemon), targets a pinned node by name or the default source, captures a sink's monitor when the default resolves to a sink (stream.capture.sink), delivers Pcm chunks and Level samples (RMS and peak per configured window), reports DeviceChanged with the old and new node when the default moves while it is followed, and ends with DeviceLost naming a pinned device that vanished, NoSource, or Stopped. TakeWriter writes takes as 16 kHz mono 16-bit WAV (microphone.wav, microphone-2.wav ...) with a takes.json sidecar recording each take's start offset, gap marker and sample count, and discard() removes a dictation take when keep_dictation_audio is off. MockCapture plays a WAV fixture (converted once to 16 kHz mono) at real time through the same event stream for DETTIVO_MOCK_MIC.

The daemon starts the audio service at boot and runs on without PipeWire (logged, audio.devices reports pipewire=false), answers the new Linux method audio.devices (pipewire, default_source, pinned, devices with kind source|sink_monitor and is_default), refuses config.set audio.input_device for a name that is not a PipeWire node with INVALID_PARAMS naming the key when the graph is available, and dettivo doctor prints an audio row (default source, device count, pin). The [audio] section (input_device, keep_dictation_audio, level_interval_ms) joins the schema, the default file, docs/config.md and the print_default fixture; the contract gains audio.devices and the audio.level payload (rms, peak, source) with a fixture and a deltas row. CI's toolchain installs pipewire and clang for the bindings.

Baseline: none (the spec defined no Quick commands). Verify: just build test lint exit 0 (with PIPEWIRE_RUNTIME_DIR pointing at the real session so the rig tests run).

Coverage: R1 tests/rig.rs a_fixture_played_into_a_null_sink_is_captured_with_levels_and_written_as_a_take: a null sink fed by pw-play is captured through its monitor, the take correlates above 0.99 with the fixture after delay alignment, and the WAV is 16 kHz mono; Graph::connect returns NoPipeWire naming PipeWire when the socket is absent (daemon log and audio.devices show it); R2 unloading_the_default_source_is_reported_within_a_second: with the sink's monitor made the default source, unloading it yields DeviceChanged from the sink to the new default within one second, and a_pinned_device_that_is_absent_is_refused_by_name; takes.rs proves a second take with its offset and gap marker; R3 level.rs windows_emit_rms_and_peak_and_silence_is_zero plus the level counts in the rig and fixture tests, AudioLevelPayload round-trips through the contract crate and the deltas additions table names it; R4 schema tests cover the keys and the default file, docs/config.md documents them, config print-default carries them, TakeWriter::discard implements the retention rule, and the daemon refuses an unknown audio.input_device naming the key (verified live: nope refused with exit 4, the real default source accepted); R5 the_fixture_path_matches_the_fixture_without_pipewire and mock.rs fixture_plays_at_real_time_with_levels_and_ends run everywhere, and a missing fixture is refused at start by DETTIVO_MOCK_MIC's parser from the QA rig spec; R6 dettivo doctor shows the audio row (verified live: PipeWire, default source, 3 devices, pinned none).

Notes for the conductor: PipeWire's default.audio.source metadata names the sink node when a monitor is the default, so default_node() resolves to an Audio/Sink and the capture sets stream.capture.sink. The audio thread finds PipeWire through XDG_RUNTIME_DIR (or PIPEWIRE_RUNTIME_DIR); the daemon test harness overrides XDG_RUNTIME_DIR, so daemon-level tests run without PipeWire and the crate's rig tests carry the real-session proof. The level events reach the socket when the events layer lands (S-07); the payload type and topic are ready. Session-level behaviour on a swap (end a dictation, restart a meeting take) belongs to S-07 and the meetings specs; the capture reports the event and TakeWriter has the take primitives.
