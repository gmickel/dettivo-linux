## Done summary
Built the MCP server and everything that connects an agent to it. `crates/dettivo-mcp` is now a library with a thin binary: a hand-rolled JSON-RPC 2.0 layer over `serde_json` (no framework crate) with a framing-detecting stdio reader that reads line-delimited JSON when the first byte is `{` or `[` and `Content-Length` framing otherwise, mirrors the detected framing for the whole session and refuses a switch as an invalid request without ending the session; the seven MCP methods (`initialize` echoing the client's protocol version and naming `dettivo-mcp` 1.0.0, `ping`, `tools/list`, `tools/call`, `resources/list`, `resources/read`, `resources/templates/list`) with notifications swallowed; the nineteen macOS tools ported verbatim from `DettivoCLI/MCP/MCPTypes.swift` (names, titles, descriptions, input schemas; `start_meeting` additionally takes `acknowledge_meeting_disclosure` as the delta register already said) and mapped one to one onto daemon methods (`get_status` = `system.health` with `system.capabilities` merged under `capabilities`; `stop_session`/`cancel_session` route to `meetings.*` when `meeting_id` is present; `get_transcript` tries dictation then meeting and keeps a `NOT_FOUND` when the meeting kind is `NOT_IMPLEMENTED`; `import_audio` uploads through `transfer.begin/chunk/commit` then `transcripts.import`; `export_transcript` binds a download, exports, pulls, writes `out_path` or returns a bounded preview and cancels the transfer on failure; `insert_transcript` sends `expected_target_pid` as the contract's string); the four meeting tools hidden exactly as on macOS while `formats.meeting_export` is empty (the Linux daemon declares meeting formats, so all nineteen are listed and the meeting tools answer the daemon's `NOT_IMPLEMENTED` with guidance); the five macOS resource templates plus `speech://providers`, `resources/list` naming the status, the providers and the newest fifty items; the macOS bounds (50 items, 100 keys, 20 000 characters, depth 8, 2 000 000 bytes) with the macOS markers (`[truncated N chars]`, `_truncated_keys`, `[truncated: max depth reached]`) and a top-level `_truncated: true` that a shortened list sets too; a message over the byte cap answered with `RATE_LIMITED_LOCAL` (`-32016`) naming the cap while the rest of the message is drained and the session continues; the daemon client with the CLI's socket and token resolution, one connection per call; and the actionable texts: the macOS hardened and timeout lines word for word, the unavailable line naming `systemctl --user start dettivod.socket`, `Unknown tool: <name>` followed by the tool list, and an `Action:` line per tool group for `NOT_IMPLEMENTED` (automation off, meetings pending, polish pending).

`dettivo mcp serve` runs the same library in-process; `dettivo mcp config --host claude-desktop|claude-code|cursor|codex [--name] [--command] [--write] [--hardened] [--json]` renders the `{type: stdio, command, args: [mcp, serve][, env]}` entry (JSON `mcpServers` for Claude Desktop at `~/.config/Claude/claude_desktop_config.json` and Cursor at `~/.cursor/mcp.json`, the `claude mcp add --scope user` line or a project `.mcp.json` for Claude Code, an `[mcp_servers.<name>]` table through `toml_edit` for Codex at `$CODEX_HOME/config.toml` or `~/.codex/config.toml`), `--write` merges into the existing file keeping every other server and key, `--hardened` or `[mcp] hardened = true` adds `DETTIVO_IPC_TOKEN = "<set-me>"`, an unknown host exits 4 naming the four; `dettivo mcp check` initialises against the daemon and prints the server, socket and auth mode, the tool count with hidden meeting tools, the template count and the framing, exit 2 when the daemon is down. `[mcp] hardened` and `max_message_bytes` joined the schema, the default file, the `print_default` fixture and docs/config.md; the server reads the cap through `config.get` and falls back to the contract's value without a daemon. The harness (`crates/dettivo-mcp/src/harness.rs`) drives a spawned server through its pipes in one framing and runs twenty steps; `crates/dettivo-mcp/tests/harness.rs` runs it in both framings against a seeded daemon, `dettivo-qa mcp` (`just qa-mcp`, mirrored in the Makefile) runs the same steps in the QA rig reported per step and framing, the contract replay's report gains the MCP section (run before the fixtures so the rows the replay deletes are still there), and the CI `drive` job runs `qa-mcp`.
