# fn-27 done summary: GPU tiers, the doctor report and the benchmark suite

The daemon now names the hardware tier and the product's numbers are a checked-in report. `system.capabilities.platform.tier` answers `gpu` when a Vulkan device is installed and no loaded engine fell back, `cpu` otherwise or under `DETTIVO_FORCE_CPU=1`, with `tier_reason`; every `speech.engines` row carries `memory_bytes`; both are registered Linux deltas with fixtures, and the supervisor honours the override for every engine it spawns (R5). `dettivo doctor --json` is the FR-D5 snapshot in one stable shape (compositor, session type, tier, portals, insertion backends, audio devices, engines with backend, reason, state and memory, models per provider, LLM readiness and provider order, socket, units, REST, MCP), pinned by a golden compared by shape; the human report groups the same rows, and an unreachable daemon still prints the machine rows and exits 1 (R1).

`dettivo-qa bench` runs `first_insert`, `stt_throughput`, `llm_rewrite`, `idle_footprint`, `startup` and the `diarization` placeholder from the fixtures the tests use, records every sample with p50, p95, min and max, the fixture hashes, model checksums, backends and reasons, host, GPU, load average at start and end, and the commit; `--cpu` forces the CPU tier, `--quick` runs three iterations, `--out` files `<date>-<host>-<tier>.json` and rewrites the README table (a headline row per step plus one row per engine). A missing model skips its row naming the download. `just bench`, `bench-cpu` and `bench-quick` mirror the Makefile; CI runs `bench-quick --cpu` in the unit job and uploads the JSON without checking it in (R2). The footprint step loads Whisper and the language model, watches `speech.engines` until both are gone (an engine still alive is named and fails the step) and samples the daemon's RSS over five idle minutes against NFR-6 (R4).

The first two reports, `docs/reports/benchmarks/2026-09-05-thor-gpu.json` and `2026-09-05-thor-cpu.json`, are checked in with the rendered README. ADR 0029 records the calibration: NFR-1 stays 1000 ms (Whisper 360 ms on the 4090), NFR-2 moves to 1500 ms stated for Parakeet (386 ms; Whisper large-v3-turbo takes 7.0 s on the CPU and is recorded beneath it), NFR-4 moves to 20x (Whisper 89x), NFR-5 moves to 5x stated for Parakeet (21.6x; Whisper 2.0x), NFR-6 stays 60 MiB (41 to 42 MiB debug), NFR-8 stays 300 ms for the socket (181 ms) and the app's first frame (395 and 349 ms in the checked-in runs, 244 to 286 ms on quieter ones: the one recorded miss). The targets live in `crates/dettivo-qa/src/nfr.rs` with `headline_provider(tier)`, and the dictation pack reads them from there (R3). `docs/qa.md` documents the suite, the report schema, the private-session-bus drive and the load-average field; `docs/daemon.md` the doctor shape and tier; `docs/RELEASING.md` the benchmark step; `docs/engines.md` tells CPU-tier users to run Parakeet (R6).

Verification: `make build test lint` green at the final commit 3bc3573 (`gate exit 0`; every Rust test binary ok, the Qt tests, fmt, clippy, crate edges, file length, deltas, QML lint, the docs check and rustdoc all passing; one earlier run flaked on fn-23's `llm_local` socket read under a sibling load average of 34, and those tests passed alone and on the rerun), the contract replay green (`mcp: 42 passed, 0 failed`, `contract exit 0`), the dettivo-qa unit tests and clippy clean, and both tiers measured end to end on thor under a private session bus with its own AT-SPI launcher and registry (the desktop's accessibility bus was wedged). The CPU report is `--cpu` on the GPU desktop, said so in its notes.

Deliberately left out: diarization throughput (placeholder until S-25), a CPU-only VM (S-16 boundary), packaging (S-31), and a tier-aware default provider (the ADR names it as the product consequence; docs tell CPU users to pick Parakeet meanwhile). Two observations from the runs are recorded in the ADR for their own specs: the daemon does not answer `system.capabilities` while a CPU Whisper transcription is in flight, and a Whisper CPU dictation that outlasts the twenty-second completion wait fails a step's remaining runs; both showed only while sibling worktrees loaded the machine to a load average above twenty. The bench daemons' stderr is now kept under `qa-evidence/<run>/bench/<step>-daemon.log` so such a run can be read back.
