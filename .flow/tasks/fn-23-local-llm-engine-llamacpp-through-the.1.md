## Done summary
Built the local language model engine and made it the default Enhanced provider. dettivo-engine-llm runs llama.cpp through llama-cpp-2 (pinned =0.1.156; CPU by default, `--features vulkan` for the ggml Vulkan backend) behind the engine protocol: load names a model file and a context_length, every layer goes on the Vulkan device with the most memory (a discrete GPU before an integrated one) when the build carries the backend, a device enumerates and the file fits its free memory, and the CPU otherwise with the reason (a failing Vulkan load under auto retries on the CPU; backend = vulkan fails instead); a missing model is model_missing naming the path and a corrupt one load_failed naming the path and llama.cpp's reason. generate replaces the placeholder shape (prompt_profile polish|raw, system, user, max_tokens, temperature, stop; answered with text, tokens, finish_reason stop|length|cancelled, backend) and streams partial events; dettivo-engine-proto gained host_llm, a streaming host loop with a reader thread so a cancel for the running request stops it between two tokens (the answer so far comes back cancelled), status answers busy meanwhile and every other request waits its turn; status gained memory_bytes (the device's usage as ggml reports it). The polish profile runs system and user through the model's chat template with an empty thinking block prefilled for a Qwen3 thinking model; the engine returns raw text and the language crate's guard strips thinking as before. --prompt <text> --model <path> [--system] [--raw] --json is the CLI mode and prints the same JSON.

The catalogue (crates/dettivo-speech/catalogue/v1.toml) lists the llm provider with kind = "llm" and roles: qwen3-4b-instruct-2507 (default, polish and analysis), qwen3-1.7b (fast), qwen3-4b (quality), qwen3-8b (analysis), the Q4_K_M GGUFs of the unsloth conversions (Qwen publishes no GGUF for 4B Instruct 2507 and only Q8_0 for 1.7B) with sizes and SHA-256 from the Hugging Face LFS pointers, Apache-2.0. llm.models.status|download|cancel|delete are the speech model shapes over that provider (is_selected marks [llm] model, an unknown id is NOT_FOUND naming the ids the catalogue lists, the selected model needs force) and llm.engine.status reports the process (found, running, loaded, busy, model, backend, reason, memory_bytes, crashes, degraded, idle_seconds); the speech methods filter to the providers with a speech model so a language model never shows up as a dictation choice. dettivo-speech::llm::LlmEngine drives the binary over the supervisor with a cancel when a generate outlives the timeout; the supervisor reaps the LLM slot on [engines] llm_idle_seconds (the spec's [engines.llm] idle_unload_seconds is folded into this already shipped key, recorded in the ADR), logs an engine that ignores unload and ends it regardless, passes context_length to load and probes a running process without loading. The local provider takes the daemon's engine through dettivo-language::provider::LocalEngine (model, probe, generate); the daemon's LocalLlm binds [llm] model to the supervisor, pipeline::Settings carries it, polish.test and every session pass it, auto prefers local the moment it probes available (file on disk, binary found, not degraded) and moves on to Ollama with the download command as the hint otherwise; system.capabilities.llm.local_available is that probe and llm.methods lists the eight methods. Config: [llm] model and analysis_model (empty means model), [engines.llm] backend, context_length (4096), max_tokens (1024); print_default regenerated. CLI: dettivo llm download|cancel|delete|status|engine beside test, and a dettivo doctor llm row. Build: build-llm, build-llm-vulkan and test-llm-vulkan in the justfile and the Makefile, the advisory llm-vulkan CI job, scripts/models/fetch-llm-test-model.sh. Docs: docs/engines.md, models.md, polish.md, config.md, the delta register rows, ADR 0026 and docs/reports/llm-idle-unload-report.json plus llm-goldens-report.json.
