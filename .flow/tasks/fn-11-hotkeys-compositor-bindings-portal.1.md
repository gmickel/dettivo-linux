## Done summary
Holding a key dictates on every desktop. `dettivo-hotkeys` carries the four actions (`PushToTalk`, `Toggle`, `Cancel`, `ReinsertLast`), the `HotkeyBackend` trait, the chord notation (`SUPER CTRL, X`, `F9`, the Lua spelling `SUPER + CTRL + X`) with renderers for every consumer, the snippet generators for Hyprland (classic `.conf` and the Lua configuration Hyprland 0.56 and Omarchy use), Sway and Niri, the portal GlobalShortcuts backend through `ashpd`, the off-by-default evdev backend with the `input` group requirement in every refusal, MPRIS pause and resume, and a mock portal plus mock MPRIS player on a private `dbus-daemon` for the tests. The daemon runs one action path for the CLI, the portal and evdev; every start captures the focused window before the microphone opens and hands it to the ADR 0007 chain as the guard, so a focus that moved refuses the insertion with `CONFLICT` and keeps the transcript; a press while a session runs is ignored with a log line; `hotkeys.status` and `system.capabilities.hotkeys` report the backend, both availabilities with reasons and the bound actions; `[hotkeys]` is a full `config.toml` section; sounds play through `pw-play` (logged through the mock audio path in QA mode). The CLI gains `dettivo setup hyprland|sway|niri [--stdout] [--check]`, `dettivo hotkeys status`, the doctor rows and `dictation start --expected-target-*`. The QA rig gains `hotkeys_hyprland`, which loads the rendered snippet into the running Hyprland and presses real chords through a `uinput` keyboard. `docs/hotkeys.md` and ADR 0016 explain the three paths and the Omarchy defaults.

### Decisions

- Omarchy's Voxtype keys are the defaults exactly as Omarchy binds them: `hold = "F9"`, `toggle = "SUPER CTRL, X"` (the spec's config example had the two inverted; the masterplan milestone "hold F9 in ghostty" and Omarchy's `default/hypr/bindings/voxtype.lua` agree on F9 as the hold). `reinsert = "SUPER CTRL SHIFT, X"` because `Super+Ctrl+R` is Omarchy's reminder key. The Hyprland snippets start with `unbind` lines for the two Voxtype chords.
- Hyprland 0.56 and Omarchy run the Lua config parser (`hl.bind(keys, hl.dsp.exec_cmd(...), { release = true })`, `hyprctl keyword` refused); `dettivo setup hyprland` renders the Lua flavour when `hyprland.lua` exists and the classic `.conf` otherwise; `hyprland-lua`/`hyprland-conf` force one.
- `dettivo-hotkeys` depends on `dettivo-proto` only (dev-dep on `dettivo-core` to pin the chord defaults to the schema); the CLI links it with `default-features = false` (snippets only), the daemon with `backends`; `mock` is a default feature so the crate's own tests and the daemon's dev-dependency get it, while the workspace declares the crate with default features off. The edge table gains the crate and the CLI edge.
- `F13`–`F24` are not chord names: the standard xkb rules deliver those evdev codes as `XF86Tools` and friends, which is why the first drive attempt with `F13` never fired.
- The portal on Hyprland answers `NotAllowed: An app id is required` for the daemon even inside an `app-*.scope` (tried); `auto` logs that at info and reports it in `hotkeys.status`, the daemon keeps serving. The portal backend is proven against the mock; a live GNOME/KDE run is a follow-up.
- Test daemons no longer inherit `DBUS_SESSION_BUS_ADDRESS` (both test crates) and the QA profile pins `[hotkeys] backend = "none"`, so no test ever binds through the desktop's real portal (a dialog on KDE).
- `dictation.stop` gains a Linux `insertion` block and `dictation.status` a `target` block; both optional on the wire, fixtures unchanged, register updated. `hotkeys.status` is a new Linux addition with a fixture; the replay levels it (machine-specific) and `contract.rs` checks its shape.
- Sounds: cues are synthesized once as 16 kHz WAV files and played with `pw-play`; the in-process PipeWire playback stream is not built (documented). The mock audio path (`DETTIVO_MOCK_MIC` or mock mode) logs cue names to `qa/sounds.txt`. The meeting flag does not exist yet; `sound_allowed(sounds, meeting)` is in place and `Feedback::meeting_active()` answers false until S-23.
- The session inserter is the real chain now (`ChainInserter` in `dettivod`), replacing the clipboard-only stand-in from S-07; `reinsert_last` runs unguarded.
- `dettivo-speech`'s supervisor tests copied the fake engine per test while other test threads spawned it, which produced `ETXTBSY` under full-suite load (seen once in the gate, pre-existing); the copy now happens once per process and each test hard-links it.
