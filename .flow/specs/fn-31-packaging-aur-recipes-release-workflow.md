## Goal & Context

<!-- Goal & Context: 30% [user], 50% [paraphrase], 20% [strategy] -->

`yay -S dettivo-bin` installs the whole product on Omarchy and a tagged commit becomes a release without a hand step. `scripts/package.sh` already stages a release tree; this spec makes the tree complete (every engine with the Vulkan and CPU backends, the QML module, the units, the desktop entry and icons, shell completions, `NOTICE.md`, the Omarchy plugin folder), writes the two AUR recipes under `packaging/aur/`, adds the release workflow that builds the tarball in the pinned Arch container, signs its checksums into `SHA256SUMS`, takes the notes from `CHANGELOG.md` and publishes them on a `v*` tag, with a dry run that does everything but publish. The install is tested where it matters: a clean container in CI installs the built package, checks every file and unit, renders the app from the installed module and runs the CPU-fallback smoke; the release gate adds the same script on a fresh VM with a user session so socket activation and `dettivo setup omarchy` are exercised for real. [paraphrase]

## Architecture & Data Models

<!-- Architecture & Data Models: 55% [paraphrase], 45% [inferred] -->

- Install layout (`scripts/package.sh` and the CMake install rules): `/usr/bin/{dettivod,dettivo,dettivo-mcp,dettivo-qa,dettivo-app,dettivo-osd}`; engines at `/usr/lib/dettivo/engines/dettivo-engine-{whisper,parakeet,llm,diarize}`, each built with `--features vulkan` for release and falling back to the CPU at run time; the module at `/usr/share/dettivo/qml/Dettivo` and `DettivoStyle` with their `qmldir`; `/usr/share/dettivo/omarchy/` (the plugin folder); `/usr/lib/systemd/user/{dettivod.socket,dettivod.service,dettivo-osd.service}`; `/usr/share/applications/dettivo.desktop`; `/usr/share/icons/hicolor/scalable/apps/dettivo.svg` plus 16, 32, 64 and 128 px PNGs rendered from the mark; completions under `/usr/share/bash-completion/completions/`, `/usr/share/zsh/site-functions/` and `/usr/share/fish/vendor_completions.d/` generated by `dettivo completions <shell>` (clap_complete); `/usr/share/licenses/dettivo/LICENSE` and `/usr/share/doc/dettivo/NOTICE.md`. Engine discovery order in `dettivo-speech`'s supervisor: `[engines] directory`, then `/usr/lib/dettivo/engines-cuda` (the reserved drop-in for the later package), then `/usr/lib/dettivo/engines`, then beside the daemon binary; `speech.engines` reports which directory answered. [inferred]
- `NOTICE.md` at the repository root lists every vendored or reused component with its license (whisper.cpp, parakeet.cpp, llama.cpp, ggml, the Qt modules, the fonts, any Voxtype seam per Principle 11); `cargo about` or an `xtask lint-notice` check keeps it in step with `Cargo.lock`. [inferred]
- `packaging/aur/dettivo-bin/PKGBUILD` (`source` = the release tarball and `SHA256SUMS`, `depends` = `qt6-base`, `qt6-declarative`, `qt6-svg`, `qt6-wayland`, `layer-shell-qt`, `pipewire`, `vulkan-icd-loader`, `libxkbcommon`; `optdepends` = `omarchy` for the bar, `ollama`; `package()` copies the tree; `provides=dettivo`, `conflicts=dettivo`; a `.install` file printing `dettivo setup omarchy` and the socket enable line) and `packaging/aur/dettivo/PKGBUILD` (`makedepends` = `rust`, `cmake`, `ninja`, `vulkan-headers`, `spirv-headers`, `shaderc`, `just`; `build()` = `just package`; the same `package()`); `.SRCINFO` generated by `makepkg --printsrcinfo` and checked in step by a test. `packaging/aur/publish.sh` pushes both to the AUR from a release, gated by a secret and never run in CI. [inferred]
- `.github/workflows/release.yml`: on `push` of `v*` tags and `workflow_dispatch` with `dry_run`; one job in the pinned container runs `just build test lint`, `just package` (release profile, the three Vulkan engine builds), `makepkg` for `dettivo-bin` against the local tarball with `namcap` clean, `scripts/packaging/install-test.sh` in a second clean container, extracts the tag's section from `CHANGELOG.md` (Keep a Changelog headings; a tag with no section fails), and publishes the release with the tarball, `SHA256SUMS` and the notes through `gh release create`; `dry_run` uploads the same three as workflow artifacts instead. The tag's version must equal `Cargo.toml`'s. The `ci.yml` `package` job runs `just package` plus the install test on every push so a packaging break is caught before a tag. [inferred]
- `scripts/packaging/install-test.sh`: installs the package with `pacman -U` on a clean root, compares the file list with `packaging/manifest.txt`, runs `desktop-file-validate`, `systemd-analyze verify --user` on the units, `dettivo --version`, `dettivo completions zsh`, `dettivo-app --render /tmp/home.png --sample --open home` with `QT_QPA_PLATFORM=offscreen` against the Home crop (the module resolves from `/usr/share/dettivo/qml` with no `QML_IMPORT_PATH`), each engine's `--help`, and the CPU-fallback smoke: `DETTIVO_FORCE_CPU=1` through the three engines' CLI modes on `tiny.en`, `parakeet-v2` and `qwen3-1.7b` with every result's `backend` equal to `cpu`, and `dettivo doctor --json` naming `cpu` per engine with the reason. With `--session` (the VM run) it also enables the socket, proves activation with `dettivo status ping`, runs `dettivo setup omarchy --check` and `dettivo-osd` as a service. [inferred]
- Release gate (`docs/RELEASING.md`): the packaging step joins the dictation pack, the benchmark report and the strict contract replay as a named step with `install-test.json` as its report; `dettivo-qa pack release` runs the whole gate in order. [paraphrase]

## Edge Cases & Constraints

- The whisper.cpp Vulkan shader step does not link against the container's shaderc today (the advisory job): the release build must make it link (the pinned `glslc` and the `GGML_VULKAN` flags) or the release fails; a CPU-only engine never ships as the default. [paraphrase]
- No Vulkan device on the install machine: every engine reports `cpu` with `no Vulkan device enumerates in ggml`; nothing in the package requires a GPU. [paraphrase]
- Models never ship: the tree and the PKGBUILDs carry no weights, and the install test asserts no file under `/usr/share/dettivo/models`. [paraphrase]
- A tag whose version differs from `Cargo.toml`, or a missing changelog section: the workflow fails before building. [inferred]
- `dettivo` (source) on a machine without Vulkan headers: `makepkg` fails naming the make dependency; the recipe never falls back to a CPU-only build silently. [inferred]
- `dettivo-osd.service` on Omarchy with the plugin installed: enabled by the package, exits with the panel notice (S-21), so no double pill. [paraphrase]

## Acceptance Criteria

- **R1:** `just package` produces the tree and tarball with every path in `packaging/manifest.txt` (a test diffs the list), the three engines report the Vulkan backend on this machine and `cpu` under `DETTIVO_FORCE_CPU=1`, and the module and plugin folder are where FR-B4 and S-21 expect them. Errors: a missing or extra path fails naming it. [paraphrase]
- **R2:** Both PKGBUILDs build with `makepkg` in the CI `package` job (`dettivo-bin` from the local tarball, `dettivo` from the source tree), `namcap` reports nothing, `.SRCINFO` matches `makepkg --printsrcinfo`, and the resulting package installs on a clean Arch container through `scripts/packaging/install-test.sh` with every check green including the CPU-fallback smoke and the installed-module render. Errors: a failed check names the step in `install-test.json`. [paraphrase]
- **R3:** `release.yml` with `dry_run` on this branch uploads the tarball, `SHA256SUMS` and the notes extracted from `CHANGELOG.md` as artifacts and publishes nothing; a tag run publishes the release with the same three files and the checksums verify against the download. Errors: a version mismatch or a missing changelog section fails the job before the build. [paraphrase]
- **R4:** On a fresh CPU-only VM with a user session, `install-test.sh --session` installs the package, proves socket activation under 300 ms, runs `dettivo setup omarchy --check` (or the plain Hyprland arm), starts `dettivo-osd.service`, and completes one dictation from the fixture through `DETTIVO_MOCK_MIC` to the insert target on the CPU tier within NFR-2; the run is recorded as the packaging step of `dettivo-qa pack release`. Errors: a step that fails names the unit or command and its exit code. [paraphrase]
- **R5:** `NOTICE.md` names every vendored component with its license and the `lint-notice` check fails when `Cargo.lock` gains a dependency the notice does not cover; `dettivo completions` for the three shells install and load (`zsh -c 'autoload -U compinit; compinit'` exits 0). Errors: as stated. [inferred]
- **R6:** `docs/RELEASING.md` documents the whole gate (dictation pack, benchmark, strict contract replay, packaging step, changelog and docs, the tag), `docs/install.md` covers `dettivo-bin`, `dettivo`, the layout and the engine discovery order, `docs/config.md` documents `[engines] directory`'s order, and an ADR records the install layout, the reserved CUDA drop-in and the release workflow. Errors: `just docs` fails on a missing key or an unindexed ADR. [paraphrase]

## Boundaries

- No `dettivo-engines-cuda` package, AppImage, Flatpak or Snap (v1.x and later per ADR 0013). [paraphrase]
- No AUR publish from CI; `publish.sh` is run by hand with the release. [inferred]
- No changes to the plugin content (S-21) or the benchmark report (S-16). [paraphrase]
