## Goal & Context

<!-- Goal & Context: 30% [user], 50% [paraphrase], 20% [strategy] -->

The product becomes readable and the release becomes a script. Four guides under `docs/guides/` give each reader one path through the topic pages that already exist: the user guide (install, first run, dictate, modes, history, meetings, settings, when something fails), the agent guide (the CLI tree from Appendix E with the Linux additions, `--json` and exit codes, MCP per host, REST, capability flags and the delta register), the Omarchy guide (the bar, the panel, `dettivo setup omarchy`, themes, keys, plugin updates) and the QA guide (the rig, the packs, visual, bench, how to write a scenario). `just docs` grows into the docs build: the CLI tree and the config keys are goldens, every page is reachable, every guide opens value first. `dettivo-qa evidence-map` proves NFR-10 by mapping every v1 R-ID to a route that exists. `dettivo-qa pack release` is the QA-9 script with named steps and JSON output, executed for the v1 candidate on this desktop with its report checked in. The Voxtype reuse review walks Appendix B area by area, and `NOTICE.md` carries every direct reuse under a lint. [paraphrase]

## Architecture & Data Models

<!-- Architecture & Data Models: 55% [paraphrase], 45% [inferred] -->

- Guides (`docs/guides/user.md`, `agents.md`, `omarchy.md`, `qa.md`): each drafted with the prose skill, opening with what the reader gets, then the path through `docs/app.md`, `dictation.md`, `history.md`, `meetings.md`, `config.md`, `mcp.md`, `rest.md`, `omarchy.md`, `install.md` and `qa.md` by link rather than by copy, so a topic page stays the one place a fact lives; `README.md` links the four under one heading and `CONTRIBUTING.md` names the rule that a behaviour change updates its page in the same commit. The agent guide's CLI tree is generated by a new `dettivo docs cli-tree` (clap's command graph rendered as the Appendix E text with `*` on every verb the delta register lists as a Linux addition) and pasted between markers the build compares. [inferred]
- Docs build (`scripts/check-docs.sh`, run by `just docs` and the CI `docs` job): the existing checks plus a CLI-tree golden (the marked block equals `dettivo docs cli-tree`), a config-key check (every key of `dettivo config keys --json` appears in `docs/config.md`, already a lint, now owned here), a reachability check (every `docs/**/*.md` is linked from `README.md`, a guide or the ADR index), a value-first check (the first paragraph under a page's H1 does not begin with `Note`, `Warning`, `Caveat`, `Before you`, `This document`), and the QA-variable table check the hosts' tests already run; each finding names the file and the line. [inferred]
- Evidence map (`crates/dettivo-qa/src/evidence_map.rs`): `qa/evidence-map.toml` lists, per spec id under `.flow/specs/` and per R-ID, a route with a `kind` (`unit`, `contract`, `pipeline`, `drive`, `visual`, `pack`, `bench`, `docs`) and a `ref` (a test name, a fixture path, a scenario id, a manifest surface, a pack step, a bench step or a doc path); the verb reads every spec's R-IDs, checks each has a route and each `ref` resolves (`cargo test -- --list`, the fixtures directory, `dettivo-qa drive list`, the manifest, `pack list`), and writes `docs/reports/evidence-map.json` and `.md` with coverage per spec; coverage under 1.0 exits 1 naming the R-IDs. [inferred]
- Release gate (`crates/dettivo-qa/src/pack/release.rs`, the ADR 0017 model over whole commands): steps `version_match` (tag, `Cargo.toml`, the changelog section), `ci_green` (`gh run list` for the sha), `contract_strict` (`dettivo-qa contract --strict`), `mcp_harness`, `pack_dictation`, `pack_gui`, `pack_meetings`, `visual` and `visual_canary`, `bench_report` (a checked-in report for this host and both tiers at this version), `install_test` (the packaging spec's script with `--session`), `evidence_map`, `docs_build`, `notice_lint`, `real_headset` (one real-microphone dictation on this desktop, recorded per the 12 risk row); each step's report is embedded, the blockers list is the union of the steps' blockers, and the "only external blockers remain" claim is the report's `external_blockers` array, empty or named. The executed run for the v1 candidate is checked in as `docs/reports/release-gate/<version>.json` with its `.md`. [inferred]
- Voxtype review (`docs/reports/voxtype-reuse-review.md`): one row per Appendix B area with the posture, the Dettivo files that implement the area, the verdict (`clean-room`, `behavioural`, `direct-reuse`) and, for direct reuse, the `NOTICE.md` entry and the upstream file and commit; a source marker `// Reused from Voxtype (MIT), see NOTICE.md` on every reused span; `scripts/lint-notice.sh` (the packaging spec's check) gains the rule that every marker has a `NOTICE.md` row and every Voxtype row has a marker, failing by path. [paraphrase]

- No daemon methods, no config keys. [inferred]

## Edge Cases & Constraints

- A spec whose R-ID is covered by another spec's route: the map allows one route to serve several R-IDs, named on both. [inferred]
- An R-ID with no automated route (Gordon's beauty review): kind `human` with the receipt path, counted as mapped and listed separately in the report. [inferred]
- A gate step that cannot run here (the CPU VM row of the benchmark): an external blocker named with the machine it needs, never a silent skip. [paraphrase]
- A topic page the guides do not link: the reachability check fails by path; the page is linked or removed. [inferred]
- A Voxtype-derived span without the marker: the review lists it and the lint fails until the marker and the notice row exist, or the span is rewritten clean-room. [paraphrase]

## Acceptance Criteria

- **R1:** The four guides exist, open value first, link every topic page, and the agent guide's CLI tree equals `dettivo docs cli-tree` with the Linux additions marked; `just docs` passes on the branch. Errors: a stale tree fails the build naming the first differing line. [paraphrase]
- **R2:** The docs build fails on a plant for each new check (an unlinked page, a caveat-first paragraph, a config key missing from `docs/config.md`, a changed CLI verb) naming the file, and passes on the branch in the CI `docs` job. Errors: as stated. [inferred]
- **R3:** `dettivo-qa evidence-map` reports 1.0 coverage of every R-ID in every v1 spec with every `ref` resolving, the report is checked in under `docs/reports/`, and a spec with an unmapped R-ID (fixture test) exits 1 naming it. Errors: an unresolvable `ref` names the kind and the reference. [paraphrase]
- **R4:** `dettivo-qa pack release` runs every named step with JSON output, embeds each step's report, and names every external blocker; the executed run for the v1 candidate on this desktop is checked in as `docs/reports/release-gate/<version>.json` with `external_blockers` naming the CPU VM rows and nothing else unexplained. Errors: a failed step exits 1 naming it; a missing checked-in benchmark report for this version fails `bench_report` naming the path. [paraphrase]
- **R5:** The Voxtype reuse review covers every Appendix B area with the files and the verdict, every direct reuse carries the marker and the `NOTICE.md` row, and `scripts/lint-notice.sh` fails on a planted marker without a row and on a planted row without a marker, by path. Errors: as stated. [paraphrase]
- **R6:** `docs/RELEASING.md` documents the whole gate step by step with the report it quotes, `docs/guides/qa.md` documents the evidence map and the gate, `README.md` and `CONTRIBUTING.md` link the guides and the same-commit rule, and an ADR records the guides layout, the docs build checks, the evidence map and the gate script. Errors: `just docs` fails on an unindexed ADR. [paraphrase]

## Boundaries

- No rendered site or hosted docs; Markdown in the repository is the deliverable. [inferred]
- No changes to product behaviour; a gap a guide exposes is filed against the owning spec. [inferred]
- No AUR publish, tag or release run; the gate report is the input to the release the packaging workflow makes. [paraphrase]
- The masterplan and the research stay in the vault; nothing from them is copied into the guides. [paraphrase]

## Decision Context

### Motivation
<!-- scope: business -->

- A product an agent or a person cannot read is not shipped, and a release whose gate lives in someone's head is not repeatable; the guides, the evidence map and the executed gate are the difference between a repository and a release. [paraphrase]
