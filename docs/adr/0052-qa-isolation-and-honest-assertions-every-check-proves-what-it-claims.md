# 0052. QA isolation and honest assertions: every check proves the behaviour it claims, or fails naming what it could not prove

Status: Accepted 2026-09-06

## What this gives you

A green QA row means what it says. The visual matrix holds an approved render to its colour and size as well as its structure, the app's renders run the same style check as every other host, Home and every settings section sit in the matrix on every theme and scale, `dettivo mcp check` speaks MCP to a served child before it reports a framing, the live-meeting scenario proves provisional text reached a consumer while the meeting ran, the history and rig scenarios judge the rows and the samples they were asked about, and the contract replay's skipped fixtures are tied to the daemon tests that cover them. Where a check previously accepted a weaker fact than the one it named, it now asks for the named fact.

## Situation

Ten read-only reviews of main 28b4b7d by another model (the fn-50 spec groups their findings by theme) found scenarios and gates whose assertions accepted less than the behaviour the spec asked for. Each finding was verified against the code first; the ones below held and are fixed with a regression test that fails before the fix. The task summary lists every finding with its commit or its rejection evidence.

- The visual comparator scores structure only and stretches the candidate to the baseline's width, by design, so that one Black Gold artboard can check a light render (ADR 0021). An approved render of the same theme and scale was compared the same way, so a palette swap or a wrong window size passed against it, and ADR 0021 records the accent-only canary scoring 0.98.
- `dettivo-app --render` grabbed its window on its own and never ran the negative style check, so the app surfaces in the matrix were the only ones a stock control or fallback font could pass through. The Home route was checked by a separate script on two themes at 1x, first run listed four themes, and General stood for four other settings sections.
- `dettivo mcp check` reported both framings from the enum's names after two daemon calls; no MCP message was ever framed.
- `meeting_live` collected the notifications only after the stop, so provisional-then-final ordering proved nothing about delivery during the meeting; `meeting_rig` judged the system track's continuation by subtracting one second of samples, which counted audio recorded before the switch; the history wait accepted the right row count with the wrong rows and treated a list with no bounds as full past its fold; the history re-run wait accepted any status but `transcribing`, failure included; the settings round trip's number comparison passed when both integer parses were `None`.
- The negative-text scan read names only and dropped a whole string when it contained the profile root, so a real path or a diagnostic beside it hid; the cua tree parser cut a name at its first quote and the no-hits scenario accepted the prefix; the bar scenario accepted an after-take crop that merely scored no worse than the listening crop; the audio rig matched sink names as substrings and left a module loaded when its monitor never appeared.
- The contract replay skipped stateful fixtures with the sentence "covered by the daemon's tests" and nothing checked that sentence; the packaging checks passed a package with no plugin and a session whose setup failed; ADR 0034 and ADR 0004 still read as governing where later records had settled the matter.

## Decision

- **Approved renders are held strictly.** `dettivo-visual-diff compare --strict` requires the same image size and a per-cell mean-colour distance under `--colour-tolerance` (0.06 by default, `colour_tolerance` per surface in `qa/visual/manifest.toml`) on a 36-row grid, on top of the structure score; `dettivo-qa visual` uses it whenever the baseline is an approved render and keeps the structure-only comparison for artboard crops, which are drawn in another theme. The canary has axes: `DETTIVO_QA_CANARY=all|colour|type|spacing` (`1` and `true` still mean `all`), `dettivo-qa visual --canary --canary-axis colour` judges the approved entries alone, and the report carries the colour distance per entry. This amends ADR 0021, whose colour-blind score stays the artboard comparison.
- **Every host renders through `renderAndQuit`.** The app's own grab is deleted; its CTest registers the render and the two planted checks. Home is the `home` surface of the manifest (four regions of `home.png`, Black Gold crops cut by `scripts/design/crop-baseline.py`), the separate script, its crop script and its CTest are gone, first run runs on every theme, and the five pattern sections of Settings are five entries. New entries report `first-approval` until a person approves them with `dettivo-qa visual approve`; the matrix never accepts a generated reference on its own. This amends ADR 0020.
- **`mcp check` performs the handshake it reports.** The command runs `dettivo mcp serve` as a child once per framing, sends `initialize`, `notifications/initialized`, `tools/list` and the `get_status` tool within 20 s, kills a child that never answers, and prints per framing which steps answered; a framing that fails the handshake fails the command with exit 1.
- **Scenarios assert the fact they name.** `meeting_live` reads notifications while the meeting runs, stamps each with its arrival and whether it came before the stop, and requires a provisional segment per source before the stop; `meeting_rig` records the switch instant on the capture clock and requires the second system fixture to be found after that boundary; `history_seed::shows` judges row identity and order in every branch and never treats an unbounded list as full; the re-run wait accepts only `completed` with the fixture transcript and fails on `failed`; the settings comparison compares parsed numbers only and whole tables; the negative-text scan reads values as well as names and removes only the exact profile-root span before classifying; the cua parser reads a name to its closing quote and decodes `\"`, and the no-hits scenario requires the whole sentence on both drivers; the bar scenario requires the after-take crop to reach the same identity score (0.999) against idle that a change must fall under; the audio rig unloads the named sink only and rolls back a load whose monitor never appears.
- **A skipped fixture names a test that exists.** `dettivo-qa`'s tests read every file under `crates/dettivo-qa/src/stateful.rs`'s list, derive the method from the fixture name and fail unless a daemon integration test under `crates/dettivod/tests/` calls that method by name. The packaging manifest lists the plugin file by file, the session install check judges the setup's exit status and reads the desktop, and ADR 0034 and ADR 0004 point forward to ADR 0040 and ADR 0018.

## Consequences

- The visual matrix grows by Home (4 states), Tokyo Night on first run (9 states) and four settings sections; every new theme-and-scale cell is a `first-approval` row until approved, so `just qa-visual` reports them by name and the nightly rig stays red until a person has looked. That is the intended state: the matrix's claim of every surface on five palettes at two scales is now checked rather than assumed.
- The strict colour check can be tripped by a font that rasterises differently between the machine that approved a render and the machine that compares it. The tolerance was chosen so glyph antialiasing averages out on the 36-row grid while an accent swap fails; a surface that needs more room names its own `colour_tolerance` in the manifest, with the reason beside it. The dialogs of History (export, re-run, confirmation) have no render switch yet and stay outside the matrix; adding one is app work for the History owner and is recorded in the task summary.
- `dettivo mcp check` now takes two handshakes' time and needs a working `dettivo` binary on its own path, which is the situation of every host that will run it.
- On cua-driver, which gives the list no bounds, a history seed longer than the view can no longer pass by count; that row fails with the reason "unbounded, so the fold cannot be proven" until the driver reports bounds, which is the honest state of that driver (ADR 0041 classes such a row as the driver's blocker when the AT-SPI twin passes).
- The bar scenario's idle criterion is symmetric with its change criterion. A clock that ticks between the idle and the after captures scores under identity and fails the row; the cure is the widget-specific crop, which needs the module's position from the shell and is left for the bar's owner.
