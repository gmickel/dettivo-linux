# 0055. Completion, capture and client actions follow authoritative state

Status: Accepted 2026-09-10

## What this gives you

Recorded audio survives a failed result write, interrupted meetings can retry their retained inputs, and settings, accessibility actions and exports preserve the values you supplied. Protocol clients receive bounded responses and can distinguish a request, an error and an unavailable comparison.

## Situation

The 33 historical findings in fn-53 covered daemon completion, audio capture, client protocols, meeting recovery, QA evidence and Qt controls. Current behavioral tests disproved qt-hosts/F8 and qml/F16. The app already uses the shared renderer and rejects both planted style defects; Home already enters the existing meeting setup flow. Shared popup opacity also already holds, but its unused meetings-only frame remained registered. Confirmed defects received regression reproductions before their fixes; deleting the unused frame retained the passing opacity behavior.

## Decision

- Jobs publish success and invoke downstream completion only after the authoritative row is stored. A failed write publishes failure, clears busy ownership and preserves decoded input for recovery. Capture also refuses downstream work when saving its stopped or transcribing state fails. This closes daemon/F7.
- Request deserialization preserves an explicit null ID. It receives a null-ID response; only an omitted ID is a notification. Overflow draining retains responsibility for drops arriving during delivery, even when publishers stop. These close daemon/F16 and daemon/F17.
- REST, CLI and MCP calculate upload chunks using both the raw transfer cap and the serialized socket envelope cap, including authentication and base64 expansion. CLI waiting polls the addressed transcript's facts, so the newest listing page cannot hide an active import. These close agent-surfaces/F3 and F13.
- MCP bounds each complete serialized response in both framings. An oversized result becomes a bounded `-32016` error retaining its request ID. If even the ID and minimal error cannot fit, the session ends without writing an oversized message. A refused framing switch cannot dispatch its payload. These close agent-surfaces/F6 and F9.
- CLI-originated failures under `--json` produce one error object with code `-32603`, `data.origin = cli` and the exit code. Daemon errors and commands with an existing structured failure report retain those shapes. Quiet mode suppresses stdout; stderr retains the failure message. MCP serving reserves stdout for framed protocol. This closes agent-surfaces/F16.
- Engine status and capability tier read published snapshots while inference owns the engine slot. Idle reaping skips occupied slots. The engine transport preflights headers and aggregate attachments before writing or allocating; its attachment ceiling is 460,800,000 bytes, enough for four hours of 16 kHz mono PCM. Diarization rejects larger tracks before reading samples. These close engines/F2 and F11.
- Dictation requests capture stop before draining. `Ended` follows the final accepted PCM, with publication serialized across device and stream callbacks. A missing acknowledgement fails within two seconds. Startup holds the graph loop lock across selection, validation, subscription and connection, with subscriptions installed before connecting. These close dictation/F19 and F20.
- `meetings.recover` accepts partial, failed, cancelled and stopped rows whose retained input validates. Captures and imports use their respective input layouts while retaining the meeting ID and notes. The GUI derives Recover from the server's recoverable list and offers Cancel transcription for running rows. `meetings.cancel` also cancels imported retries and preserves notes edited during the job. A stopped daemon's interrupted transcription becomes a recoverable failed row. The microphone retries an unavailable device every 500 ms and creates a take only after reopening succeeds. These close meetings/F5 and F6.
- Finalization rejects damaged manifests, missing or invalid expected WAVs, mismatched sample counts and unlisted takes. Take-close failures remain failures and preserve audio. Recovery reconciles sidecar, checkpoint and journal identities, orders takes by their offsets and measures duration through the latest take end, including gaps. Unknown timing remains an explicit recovery problem. These close meetings/F7 and F8.
- Combined transcript search orders both kinds by folded exact-title match, then recency and stable reference, before applying the limit. Independent FTS ranks do not decide which kind remains visible. This closes meetings/F14.
- Export selects a notes override before checking whether it is empty. An explicit empty or whitespace-only draft suppresses saved notes. The app passes the live draft; absence requests saved notes. Speaker names reject control characters; subtitle rendering flattens payload whitespace and escapes markup while leaving stored text unchanged. These close meetings/F17 and F18.
- The live Omarchy QA drive owns the job it starts and conditionally cancels that job on an unsuccessful exit. `dictation.cancel.expected_job_id` checks identity under the session lock; a replaced job returns `NOT_FOUND`. Cleanup errors remain attached to the original failure. This closes qa-rig/F6.
- Relative polish promotion requires matching selected content, split, ordered row IDs, scoring rules, targets, runtime binaries, runner, host and execution switches, plus the backend. `gate.absolute_passed` reports absolute acceptance; an unavailable requested comparison cannot set `gate.passed`. Old reports remain readable and require a fresh incumbent run for promotion. This closes qa-packs/F15.
- Visual approval renders and validates the complete selection and provenance before publishing. Ordinary publication failures restore previous files and remove newly created files. A failed rollback names its affected path and retains the original backup where possible. This closes qa-packs/F18 without approving any existing visual difference.
- Import preview and playback share a WAV metadata reader with checked 64-bit offsets, padding bounds and an 8,192-chunk inspection budget. Malformed input produces unknown preview duration; daemon import remains authoritative. The app discovers active meetings after subscription acknowledgement and reconciles on overflow and reconnect. Theme timing credits a generation only after its scene-graph synchronization and swap; the app journal consumes that same collector. These close qt-hosts/F4, F11 and F16.
- Segmented controls request a selection and preserve their owner's binding. Accessibility actions invoke actual activation exactly once. Transcript, title, speaker and analysis labels use plain text. Settings suppress duplicate Enter/blur commits only within one editing session. The unused DialogFrame and its registrations are removed because the shared floating surface is already opaque. These close qml/F1, F2, F6, F7 and F8.
- The bar sends the retained meeting ID through an observed stop command and refreshes after completion. Start opens the app's existing setup and disclosure flow. Reconnect invalidates stale snapshots. This closes ops-and-record/F6.

## Consequences

Contract corrections and consumed fixtures are registered in [the Linux delta register](../api/linux-deltas.md). The task receipt lists each finding's disposition, its regression evidence and the final repository and native-drive results.

Busy engine memory is the last observed resident set. Four-hour diarization still materializes about 439.5 MiB of PCM. Imports configured beyond four hours can transcribe, but their diarization refuses that duration. A missing recovery timeline preserves audio for inspection instead of assigning every take offset zero. Recovery through the API and CLI can retry failed imports; discard keeps its partial-only contract.

Multi-file visual publication rolls back ordinary errors; it does not promise crash-atomic replacement. Earlier live meeting segments remain unreplayed after attachment. The always-on theme journal collector retains no frame history. The existing visual approval boundary, golden images, tolerances and physical-display performance requirements remain in force.
