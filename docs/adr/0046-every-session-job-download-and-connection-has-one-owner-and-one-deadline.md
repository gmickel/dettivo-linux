# 0046. Every session, job, download and connection has one owner and one deadline

Status: Accepted 2026-09-06

## What this gives you

A second `dettivod` on the same data exits before it can mark the first daemon's imports failed or recover a meeting it is still recording. A dictation start and a meeting start racing over two connections leave exactly one session active. A cancel pressed while the language model rewrites a take stops the insertion and the archive, and a cancel chord pressed while push-to-talk is held is heard at once. A token rotation or an `ipc.auth_mode` change reaches every open connection on the reload. Every timeout in the daemon, the REST shim, the Qt clients and the QA rig now bounds the whole operation it wraps, and a timed-out engine, request or helper leaves a state the code can name. This record closes the twenty-three findings of the fn-44 review theme (ownership, races and lifecycle) and names what each fix rules out.

## Situation

Ten gpt-6-astra reviews of main 28b4b7d, grouped by theme in spec fn-44, found the same shape in eleven places: a resource with two owners, a check separated from the action it guards, or a timeout that covered one step of an operation and left the rest unbounded. Each finding was verified against the code and a test before it was fixed. Every one held. The regression tests below fail on the code before the fix and pass after it.

## Decision

- **The history store has one owner (daemon/F2, meetings/F13).** `History::open` takes an exclusive `flock` on `<db>.db.lock` before `Store::open`, recovery or any row write, and holds it for the daemon's life. A second daemon on the same data exits 1 naming the holder's pid and socket, even when told to listen elsewhere. The same open settles `running` analysis and diarization passes to `failed` with the reason, keeping the earlier analysis and speaker assignment, so both retries return after a restart (`fail_stale_meeting_passes`).
- **One analysis per meeting, published under its registration (daemon/F5).** `Analysis::admit` checks and inserts the running job under one lock. `settle` writes the row and `analysis.json` while the job is still registered and compares the registration's job id to its own, so a delete that arrives during the commit waits in `cancel` and clears what was written, and a job another run replaced drops its result.
- **One capture reservation (daemon/F6).** `Daemon::capture_start_lock` is held from the dictation and meeting exclusion checks through the session start; the hotkey start goes through the same path. A start that fails releases it by drop.
- **Authentication is one snapshot (daemon/F9).** `Daemon::auth_snapshot` returns the mode and the expected token together, swapped as one on reload and read per request in the router; `Session` no longer captures a token at open.
- **One shutdown deadline (daemon/F10).** `server::run` returns the deadline `[daemon] shutdown_timeout_ms` set at the signal; the REST stop, the hotkeys, the downloads and the engines each run under `shutdown::within` against that deadline and are left behind by name when it passes. Request handlers run under `block_in_place`, so a ping on another connection answers while a handler blocks. Blocking work in a handler is still not interruptible; the deadline bounds the exit, and the engine children end on their closed pipes.
- **The selection and the load carry every setting (daemon/F13, engines/F6).** `Engines::Selected` includes the backend, so a backend-only change rebuilds the recognizer and preloader. The supervisor slot caches the whole `LoadParams` and reloads on any difference (backend preference, context length, VAD model, adapter, threads).
- **Application timing is defined (daemon/F14).** `[daemon] log_level` reloads through a `tracing_subscriber::reload` handle unless `RUST_LOG` owns the run. `docs/config.md` names the four exceptions that apply at the next start (`ipc.socket`, `paths.data_dir`, `history.db_path`, the `[rest]` listener keys). The contract does not gain a pending-state field; `config.get` keeps reporting the configured value and its source.
- **Bookkeeping ends with the work (daemon/F18, agent-surfaces/F7).** Both accept loops reap finished connection tasks in their `select!` with an `is_empty` guard, the REST loop closes the connection past `MAX_CONNECTIONS` (64) unanswered, and `ImportSlot::keep` clears an `armed` flag instead of `mem::forget`.
- **Absent is distinct from invalid (agent-surfaces/F4).** `tools/call` refuses non-object `arguments` with `INVALID_PARAMS`, and `cancel_session`/`stop_session` refuse a `meeting_id` that is present and not a string instead of cancelling the dictation.
- **One REST deadline per request (agent-surfaces/F8).** Reading, the handler and the response write share one `timeout_at` deadline. A handler that outruns it answers 500 with "its outcome is unknown" and stays tracked to its end, logged with its status.
- **No callback under the progress lock (engines/F1).** The download thread takes its final snapshot under the lock, releases it, then calls `on_progress`; the model service's status path can no longer deadlock against completion.
- **An uncertain engine is discarded (engines/F3).** The request deadline starts before the frame is written. A `load` that fails without crashing, or a request that ends in `Transport` (a timeout or a broken stream), terminates the process and clears the cached load, firing `unloaded` with the reason; the next request spawns and loads afresh. The wait for the slot lock stays outside the request budget.
- **Cancel reaches the insertion (dictation/F1, F8, F15).** The worker checks the cancel flag after the language pipeline and before `Inserting`; a cancel that arrives after delivery answers `NoSession`. The evdev matcher emits `Press(Cancel)` while another chord is held and keeps the held chord's release; the hotkey action worker runs `stop` on a thread of its own so a cancel is acted on at once. The rewrite budget starts before provider resolution, and the `secret-tool` credential lookup is killed after two seconds.
- **The rig's operations have deadlines (qa-rig/F17, qa-packs/F13).** `driver::bounded::output_within` kills a `cua-driver call` after sixty seconds; `socket::call_within` puts the write and the read under one deadline and names a timeout as `TimedOut`. `gpu_proof::Sampler` stops and joins its thread on drop. `EventStream::collect` still returns the partial list on a transport failure; the scenario's own terminal-event check judges it.
- **The app instance is settled before the window (qt-hosts/F9).** `InstanceLock` takes an exclusive lock on `app.lock` before `QGuiApplication` exists; only its holder listens on `app.sock` or replaces a stale one, and a launch that finds the lock taken forwards to the sibling for up to five seconds.
- **A Qt request fails exactly once (qt-hosts/F12).** `DaemonClient` gives each pending request a deadline (`kRequestTimeoutMs`, 60 s), fails the callback once with the wait named and the uncertainty stated, and completes a refused write through the same path.
- **The plugin restores its state from snapshots (ops-and-record/F11).** `DettivoState` re-reads `dictation status` and `meetings list --limit 1` whenever the stream reopens, keeps the meeting id, and drops a snapshot that started before a newer event (`sessionSeq`).

## Consequences

- Twenty-three findings fixed, none rejected; twenty-seven new regression tests across `dettivod`, `dettivo-speech`, `dettivo-session`, `dettivo-language`, `dettivo-mcp`, `dettivo-rest`, `dettivo-qa` and the Qt hosts, plus the extended Omarchy plugin event test, fail before their fix and pass after.
- A daemon that loses its lock file directory cannot start; the message names the path. Two daemons on different data directories still run side by side.
- A timed-out engine request sacrifices the warm model; the next request pays a load. A backend-only or context-length change reloads where it was silently ignored.
- The REST shim answers at most 64 connections at once; a 65th is closed unanswered until one closes.
- ADR 0028 (REST) is amended by the one-deadline rule and the connection cap; ADR 0020 (the Qt daemon client) by the request deadline; ADR 0036 (analysis) by the registration-held publication; ADR 0009 (configuration) by the named application timing. None is superseded.
