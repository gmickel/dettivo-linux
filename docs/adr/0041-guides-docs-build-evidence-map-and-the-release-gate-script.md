# 0041. Four guides lead the reader, the docs build holds the pages together, the evidence map proves every requirement has a route, and the release gate is one script with its blockers named

Status: Accepted 2026-09-06; amended by [0051](0051-the-release-gate-passes-on-validated-evidence-bound-to-the-tested-binaries.md): a failed row is a failure on either driver, missing CI evidence is unexplained until the API confirms the workflows are disabled, and the map is an inventory of routes

## What this gives you

A person or an agent opens one of four guides and reaches every page they need by link; a stale command tree, an orphaned page, an undocumented key fails `just docs` by file and line; every R-ID of every v1 spec is mapped to a route that exists and the map is checked on every `cargo test`; and a release candidate is judged by `dettivo-qa pack release`, which runs the fifteen gate steps, embeds their reports, and names every blocker as external or unexplained, so "only external blockers remain" is a line in a checked-in report rather than a sentence in a chat.

## Situation

Thirty-nine specs had produced twenty topic pages, forty decision records and eleven reports with no path through them: `README.md` listed the pages in a table, `docs/RELEASING.md` described three pack steps and the rest in prose, and the product plan's CLI tree lived in a vault appendix while the binary had grown twenty verbs beyond it. NFR-10 asks for every v1 requirement to be mapped to an evidence route before release, and QA-9 asks for the gate to be one script with named steps and JSON output whose "only external blockers remain" claim names them; neither existed as a file. The plan's Voxtype policy allowed direct reuse with attribution and nobody had walked the areas to say whether any had happened. The alternative on the table was a rendered site with generated navigation, which would have added a toolchain to a repository whose documentation is Markdown read in an editor or on GitHub.

## Decision

- **Guides.** `docs/guides/user.md`, `agents.md`, `omarchy.md` and `qa.md` each open with what the reader gets and walk the topic pages by link, never by copy, so a fact keeps one home. `README.md` links the four under one heading and `CONTRIBUTING.md` states the rule that a behaviour change lands with its page in the same commit.
- **The CLI tree is generated.** `dettivo docs cli-tree` renders clap's command graph (verbs, positionals, long options, the first sentence of each help) with a `*` on every path the new `CLI additions` table of `docs/api/linux-deltas.md` lists (a row marks the verb and everything beneath it); the agent guide holds the output between `cli-tree` markers and `--json` prints the same tree as data.
- **The docs build.** `scripts/check-docs.sh` keeps its ADR, link and contract-pin checks and checks these additional facts: every `docs/**/*.md` is reachable from `README.md` by a breadth-first walk over links; every key of the `config.keys` fixture is named in `docs/config.md`; the guide's tree equals `dettivo docs cli-tree`, the first differing line named. `scripts/test-check-docs.sh` proves the build on a clone with substantive failure plants and runs in `just docs`; the CI `gate` job runs `just lint`, which runs both.
- **The evidence map.** `qa/evidence-map.toml` lists, per spec and R-ID, routes of kind `unit`, `contract`, `pipeline`, `drive`, `visual`, `pack`, `bench`, `docs`, `script` or `human`; `dettivo-qa evidence-map` reads every spec's acceptance criteria, resolves every `ref` (a test function under its crate or a Qt test, a fixture path, a scenario id, a manifest surface, a pack step, a bench step, a page, an executable script, a receipt), writes `docs/reports/evidence-map.json` and `.md`, and exits 1 naming an unmapped R-ID, an R-ID the spec does not have or an unresolved reference. A unit test runs the checked-in map against the repository, so a renamed test or a deleted scenario fails `cargo test`.
- **The release gate.** `dettivo-qa pack release` runs `version_match`, `ci_green`, `contract_strict`, `mcp_harness`, `pack_dictation`, `pack_gui`, `pack_meetings`, `visual`, `visual_canary`, `bench_report`, `install_test`, `evidence_map`, `docs_build`, `notice_lint` and `real_headset` in that order as whole commands, embeds each step's report under `steps[].report`, and classifies every blocker: external when its reason names the CPU-only VM, a driver tool that is not installed, a row that fails on `cua-driver` while its `atspi` twin passes (the driver's or the owning GUI spec's defect), a workflow GitHub has disabled, the live desktop the Xvfb session cannot reach, a GPU counter or a person at the microphone; unexplained otherwise. The packs run with `--continue` so every row is in the report. The gate passes when no step failed and the unexplained list is empty. `--skip <step>` records a step as left out, `--record` files the run as `docs/reports/release-gate/<version>.json` with its `.md`, and `docs/RELEASING.md` is the same list step by step. The scenario-level `release` pack that extended the dictation pack is replaced by this one.
- **The reuse review and the notice rule.** `docs/reports/voxtype-reuse-review.md` holds one row per area of the plan's reuse policy with the files and the verdict (`clean-room`, `behavioural`, `direct-reuse`); no area carries a direct reuse. `lint-notice` gains the rule that every `Reused from Voxtype (MIT), see NOTICE.md` marker has a row in the reuse table of `NOTICE.md` and every row has its marker, failing by path; `scripts/lint-notice.sh` is the name that runs it.

## Consequences

- A change to a verb, an option or a help sentence fails `just docs` until `dettivo docs cli-tree` is pasted again; the guide can never describe a binary that does not exist.
- The map carries 817 routes over 247 R-IDs in 40 specs, 12 of them `human` receipts (the design baselines record, task receipts for what only a desktop could show); a spec whose R-ID is only provable by a person says so in the report rather than hiding behind a test name.
- The executed gate for 0.1.0 on this desktop names its external blockers in `docs/reports/release-gate/0.1.0.json`: the CPU-only VM rows of the benchmark and the install test, the meetings screens that fail on `cua-driver` and pass on `atspi`, the GitHub workflows disabled by instruction, the live-desktop steps the Xvfb session cannot reach, and the real-microphone receipt; anything in `unexplained_blockers` is a defect to fix before a tag, never a note in the release. The same run fails two steps on defects outside this record: `contract_strict` on the six `automation.macros.*` methods the daemon declares and answers as pending, and `pack_gui` on the history list showing 15 seeded rows where the scenario expects 13 since the seed gained meetings; both are filed with their owners and the report says so. The re-run after fn-41 fixed them ([ADR 0043](0043-qa-profiles-carry-a-private-models-directory-and-the-gate-passes-on-what-the-code-does.md)) is the run of record now checked in: `passed` at commit `2582ff95409a` on the Vulkan engines, 1 149 981 ms, ten blockers all external and none unexplained (`ci_green` on the disabled workflows, the three live-desktop rows, the three meetings screens on `cua-driver`, the CPU-only VM rows of `bench_report` and `install_test`, and the missing real-microphone receipt); `contract_strict` passes with the six macros methods pending behind a `false` flag, and the real models directory was byte-identical before and after the run.
- The reachability check makes a page's link its reason to exist; a report or a baseline record nobody links is removed or linked, which is why the QA guide carries the reports index.
- The docs build clones the repository once per `just docs` for the plants, which costs a second on a warm disk; the CLI-tree check builds `dettivo-cli` when `target/debug/dettivo` is absent.

The wording blacklist was removed by [ADR 0054](0054-delete-duplicate-work-and-keep-one-owner.md). Prose guidance remains a writing responsibility; the build checks structure, commands and contract evidence.
