# 0025. The history detail reads one answer, plays the take in-process and writes an export where the portal says

Status: Accepted 2026-09-04

## What this gives you

Opening a dictation in History shows the numbers the product promises (the insertion backend, the stop-to-insert time) beside the text and the take, in one round trip to the daemon; the take plays inside the app with the played portion drawn on the strip; a search paints the words that matched; and an export lands in a file you chose through the desktop's own save dialog, with the drives writing it into a directory instead.

## Situation

The macOS contract's `transcripts.get` answers the texts and the segments and nothing else; the detail in `history.png` also shows the app, the engine and model, the language, the take's length, the insertion backend and the stop-to-insert time, and whether a re-run has audio to read. The store already kept the insertion result but not the completion event's timings, so the number the product promises was gone the moment the OSD had shown it. `transcripts.search` answered a snippet with no word positions, and a list row cannot paint a match it cannot locate. The list row carried no app and no mode, so the meta line (`ghostty · Enhanced · 4 s`) had no source, and the kind filter (`All`, `Dictation`, `Meeting`, `Import`) had no field to read. Playback needed a decoder: the take is 16 kHz mono PCM by the store's contract, and the app already links Qt. An export moves through the contract's chunked download transfer; a Qt app running under Hyprland has no file dialog of its own that looks like the desktop's, while the drives run headless and cannot answer one. The seed's rows are dated in February and kept no audio, so no drive could re-run anything.

## Decision

- `transcripts.get` carries a Linux `facts` block: `created_at`, `app_id`, `app_name`, `source`, `status`, `provider`, `model`, `language`, `duration_seconds`, `title`, `rerun_of`, `audio` (`retained`, `path`, `reason` = `not_retained` or `expired`), `insertion` as it was reported (with the `backend` block) and `timings` (`capture_ms`, `transcribe_ms`, `insert_ms`, `stop_to_insert_ms`). Migration `0005-timings` stores the completion timings with the item; rows written before it have no timings and the detail shows a dash. `HistoryItem` gains `app_id`, `mode` and `source`; `transcripts.search` items gain `matches` (character ranges inside `snippet`, the same word-prefix rule the FTS expression applies, computed in the store) and `item` (the hit as a row). All of it is registered in `docs/api/linux-deltas.md` and omitted on the wire where absent, so the macOS shapes stand.
- The app plays the take through `QMediaPlayer` with a `QAudioOutput` (Qt Multimedia, the FFmpeg backend on Arch), and reads the strip's 48 bars straight from the WAV samples in the host (`HistoryPlayer::readWav`), so the strip draws the take before a frame has played and a file that is not 16-bit PCM is named rather than guessed at. Qt Multimedia joins the build's required components and the toolchain packages (`qt6-multimedia`, `qt6-multimedia-ffmpeg`).
- An export is `transfer.begin { download }`, `transcripts.export` with the format and the scope (`item` or `all`), then `transfer.pull` chunk by chunk into the file. The file is chosen through `org.freedesktop.portal.FileChooser.SaveFile` over D-Bus with the daemon's file name as the suggestion, so the dialog is the desktop's; `DETTIVO_E2E_EXPORT_DIR=<dir>` under QA mode writes the file into that directory under the same name and never opens the dialog, which is how the `history_seeded` drive reads the export back and compares it with the store's golden.
- Search filters the list to the hits and paints the matched words with the 12 % accent fill (`Theme.roleSearchHighlight`) through `Html.highlighted`, which escapes everything around the spans; the timeline returns when the query is cleared. A query with no hits shows the designed state naming the query and keeps the kind filter.
- Under `DETTIVO_E2E_SEED=1`, with `keep_audio` on and `audio_retention_days = 0`, the daemon writes one second of silence as the take of seed row 11 and points the row at it, so a drive can re-run an item; the contract sample keeps no audio, so the `audio_not_retained` fixture still replays. The age limit has to be off because the rows are dated in February and the sweep would remove the take at once; the drive and the daemon test set it.
- A render with `DETTIVO_E2E_SEED=1` and no daemon fills the models with the baseline's sample the way `--sample` does, so `qa/visual/manifest.toml` renders History from `dettivo-app` with the same variables as any other surface, and a manifest state may carry a `crop` rectangle: the render is cut to it, scaled, before any comparison, so a region of the window is held to the same region of `history.png`.
- `dettivo app open history.detail --id <uuid>` and `dettivo-app --open history.detail --id <uuid>` open a detail directly; the id travels as the instance socket's `arg`.

## Consequences

- The detail is one `transcripts.get`; the list is one `transcripts.list` page or one `transcripts.search`; a re-run is followed through the `job.progress` events the app already subscribes to, mapped to its row by the job id `transcripts.rerun` returned. A job started from the command line shows as a `transcribing` row and settles on the next page read.
- Migration `0005-timings` bumps the schema to 5; the export goldens and the stats fixture moved with it. An export of a profile whose seed keeps a take differs from the golden in one `audio_path`, which the drive and the command-line test level before comparing.
- `Html.highlighted` renders rows as rich text only while a query is set; plain rows stay plain text, so the list's cost does not change outside a search.
- Playback depends on an audio output the session offers; without one Qt Multimedia reports the error on the strip's clock line and the take still draws. Position is `QMediaPlayer`'s, so the played portion follows the decoder's clock, not a timer of the app's.
- The portal dialog is the only path that asks the person where a file goes; a desktop without a file-chooser portal gets the error named on the sheet. The QA directory bypasses the dialog only under QA mode, like every other `DETTIVO_E2E_*` variable.
- The cua driver on a scaled Hyprland desktop clicks beside small controls (the clear glyph of the search field); CI runs both drivers under Xvfb at 1x, where the pixel rung lands, and the in-repo `atspi` driver passes the drive on the desktop.
