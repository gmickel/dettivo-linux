# 0030. The Omarchy plugin is a folder in this repository, mirrored for `omarchy plugin add`, and its panel hosts the pill

Status: Accepted 2026-09-05; amended 2026-09-06 by [0051](0051-the-release-gate-passes-on-validated-evidence-bound-to-the-tested-binaries.md) (the mirror is written by the releaser after the tag, not by the release) and by 0053 (the pill consumes the idle-from-inserting completion; the bus name is claimed only while the pill can render); amended 2026-09-16 by [0063](0063-the-bar-meeting-timer-ticks-from-the-recording-anchor.md) (the meeting timer ticks from the recording anchor); amended 2026-09-24 by [0064](0064-a-release-publishes-itself-to-the-aur-and-the-plugin-mirror.md) (the release workflow writes the mirror)

## What this gives you

On Omarchy, Dettivo lives in the bar: a 16 px mark shows idle, listening, transcribing, a meeting with its timer and an error, a click opens the 340 px panel, and the recording pill is drawn by the shell itself while `dettivo-osd` steps aside. `dettivo setup omarchy` does the whole install in one command, the plugin is authored, linted, rendered and tested here at the same bar as the app, and `omarchy plugin update` fast-forwards because the folder carries no state.

## Situation

Omarchy 4 hosts the desktop in one Quickshell process, `omarchy-shell`, and a plugin is a folder with a `manifest.json` that the shell loads from `~/.config/omarchy/plugins/<id>/`; `omarchy plugin add` clones a git repository there, `omarchy plugin validate` refuses a folder with a missing entry point, a symlink or a reserved id, and the shell's `Color` and `Style` singletons are how a widget matches the bar. Quickshell resolves `import Dettivo` from its own import paths only, and the shell's environment is Hyprland's, so a package cannot add `/usr/lib/dettivo/qml` to the shell's `QML_IMPORT_PATH` without a session restart; a QML import that fails is a load error the shell logs and the widget never appears. Quickshell exposes no accessibility tree and no way for QML to claim a session-bus name, while `dettivo-osd` already exits with a notice when `dev.dettivo.OmarchyPanel` is on the bus (ADR 0015). The visual job (ADR 0021) renders every surface through a Qt binary with `--render`, which Quickshell is not. The masterplan asked for a separate `omarchy-dettivo` repository so that `omarchy plugin add` has a URL to clone.

## Decision

- The plugin's surfaces are components of the shared module: `Dettivo.BarGlyph` (the six-bar mark at `Theme.iconSize`, five states, the meeting timer, `dimmed` for the hint) and `Dettivo.BarPanel` (the 340 px panel, `Theme.barPanelWidth`, with its header, mode segment, two actions, three fact rows, the recent list and the footer; `hint` and `unavailable` are states of the same item). `dettivo-bar` renders both outside the shell for `dettivo-qa visual`: the panel's five states against the panel box cut from `omarchy-bar-panel.png` and the glyph's five cells against the strip at the foot of `osd.png`, on every theme and scale.
- The plugin itself is the folder `omarchy/` in this repository, installed by the package at `/usr/share/dettivo/omarchy` and copied by `dettivo setup omarchy` into `~/.config/omarchy/plugins/gmickel.dettivo/`. `scripts/omarchy/export-plugin.sh` writes the folder into a checkout of the `omarchy-dettivo` mirror byte for byte; the mirror's history is written by the release, never by hand, and the manifest version equals `Cargo.toml`'s so the copy is exact. The plugin's QML is a thin wiring layer: `DettivoState.qml` (a Quickshell singleton around one `dettivo --json events --follow` process and one short `dettivo --json` call per fact and per action), `BarWidget.qml`, `PanelPopup.qml` and `Panel.qml`; the three files that touch the module import it as a directory, `import "file:///usr/lib/dettivo/qml/Dettivo" as Dettivo`, which loads the module's plugin library and singletons from its installed `qmldir` without an import path, and they are reached only through `Loader`s that stay inactive until a `test -f` on the module's `qmldir` has answered, so a machine without the module shows a dimmed glyph and the install hint and the shell logs no QML error.
- The manifest declares `bar-widget` and `panel` with `keepLoaded`. The `panel` kind is the pill host: a `PanelWindow` at the `[osd]` position showing `Dettivo.Osd` fed from the same events, and a long-lived `dettivo osd host-panel` process that claims `dev.dettivo.OmarchyPanel` on the session bus while `[omarchy] osd = "panel"` and exits at once otherwise, so `service` leaves the name free and `dettivo-osd.service` keeps the pill. The popup the bar widget opens is a shell `KeyboardPanel` hosting `Dettivo.BarPanel`, not a manifest kind. `dettivo osd status` answers from the disabled notice when no pill process runs, so the hand-over is visible from the command line.
- Configuration is `[omarchy]` in `config.toml` (`glyph`, `level_meter`, `osd`, `history_items`, `open_shortcut`); the manifest's settings schema carries the first three, and the widget writes a changed setting through `dettivo config set omarchy.*`, so the file stays the source of truth (ADR 0009) and the plugin folder carries no state.
- `dettivo setup omarchy` enables `dettivod.socket`, writes the Hyprland Lua snippet the `hyprland` arm writes, copies the plugin folder (or clones the mirror with `--git`), rescans and enables it in the shell, and reloads Hyprland and the shell; `--check` reports every step as JSON and `dettivo doctor` gains an `omarchy` line. Without the `omarchy` command the plugin step is skipped with the reason.
- QA holds the folder to the shell's rules: `scripts/lint-omarchy-plugin.sh` checks the manifest fields, runs `omarchy plugin validate` where the shell is installed, and lints the QML with `qmllint --bare` against a shell shim under `qt/fixtures/omarchy-shell/` (the `Color`, `Style`, `BarWidget`, `Panel`, `KeyboardPanel`, `Process` and `PanelWindow` types the plugin uses); `tst_plugin_hints.qml` and `tst_plugin_events.qml` run the plugin under that shim, answers each process by hand, and proves the hint states, the event mapping, the actions and the bus-name claim. The `omarchy_bar` drive runs only where the shell has the plugin enabled and asserts state through the CLI and pixels through `grim`; `omarchy_osd_host` proves the pill hand-over on any desktop with a session bus.

## Consequences

- One folder, one lint, one test and one visual matrix cover the plugin; the mirror repository holds nothing that is not here, and a change to the panel is a change to `qt/qml/Dettivo/components/` with its Qt Quick Test and its baselines.
- A directory import ties the plugin to the module's install path; a package that moves the module has to update three import lines and the lint's staging script, which is the price of a plugin that loads in a shell whose import paths it cannot change.
- The plugin reads the daemon's version once at load and after every reconnect; a daemon older than `omarchy.minDettivo` shows the upgrade hint instead of half a panel, and the plugin's own version follows the package, so `omarchy plugin update` on the mirror is always a fast-forward.
- Quickshell has no accessibility tree, so the `omarchy_bar` drive asserts the daemon's state through `dettivo dictation status --json` and the bar through a `grim` crop; the panel's controls are proven by the Qt Quick Tests and the visual job, not by a driver.
- The panel's timer followed `meeting.state`'s `live_last_end_ms` and never a QML clock alone; [0063](0063-the-bar-meeting-timer-ticks-from-the-recording-anchor.md) withdraws that rule after a dogfood in which the count stayed at `00:00` through a quiet room, and the timer now ticks from the recording's anchor.

## Dogfooding correction, 2026-09-14

Omarchy setup now activates the Lua shortcuts and the shipped panel owns its control styling. The shortcut installer appends one include after existing configuration, preserves unrelated settings, reloads Hyprland and reports configuration errors. Onboarding waits for successful activation before advancing.

The plugin folder carries `qmldir` with its shared-state singleton declaration. Its loaded waveform explicitly counts as visible button content. The panel directory-imports `DettivoStyle` alongside `Dettivo`, making both packaged modules available without changing the shell environment. The panel uses explicit styled buttons and an inset, equal-width mode selector.

The isolated plugin test uses a plain Qt host with no Dettivo libraries linked, no selected Dettivo control style and no module import-path override. Staging preserves the shipped singleton declaration. This catches the three assumptions that the old shim and linked test host hid. Native clean-install and dictation acceptance remain deferred while Gordon dogfoods; this amendment records implementation decisions, not a native QA verdict.
