# 0049. The daemon reports what runs: the configuration in force, the models it verified and the backend it initialised

Status: Accepted 2026-09-06. Amends 0004 (the Vulkan preference), 0005 (model verification), 0009 (a broken file), 0023 (the endpoint trust gate and a preset's model), 0024 (the local model on first run), 0029 (the tier), 0034 (the install test), 0038 (the meeting rail) and 0043 (the profile models tree).

## What this gives you

What `system.health`, `system.capabilities` and `speech.engines` say is what is running. A `config.toml` edit that breaks the file leaves the values you asked for in force, `peer_token` and the retention among them, instead of dropping the daemon to the defaults; a value a pipeline would refuse is refused when the file is validated, by key and line. No engine opens a catalogue model that did not verify, and a model set stays `ready` only while every file still is what the catalogue names. `backend_preference = "vulkan"` is Vulkan or a refusal, and the tier says which hardware the speech engines run on regardless of the CPU-only diarization pass. A transcript sent to a language model reaches the endpoint you confirmed and no host it redirects to, under the model the policy hash names. The meeting rail, the Home Start button and first run send the daemon the requests its contract accepts, and a meeting started from the rail runs on `[meetings]` until you change a choice on it.

## Situation

A cross-model review of main `28b4b7d` (ten gpt-6-astra reviews, one per area) named eighteen places where what the daemon reported, or what a client asked it for, differed from what ran: daemon F3, F4 and F15; agent-surfaces F11; engines F7, F8, F10, F13 and F14; dictation F9 and F16; qa-rig F2 and F3; qt-hosts F5, F6 and F7; qml F5; ops-and-record F4. Each was verified against the code with a test that failed before its fix, and every one held. The pattern was the same in each area: a documented decision that was right for the common case had a fallback, a default or a field name behind it that nobody exercised. Reload installed `Config::default()` on a parse error because the daemon must start; the hosts merge treated an inline TOML table as absent because the regular case was a table; a verified manifest recorded the first download's checksum because the first model sets had one file; `Vulkan | Auto` were one arm because a GPU machine has a device; the tier counted every resident engine because every engine had a GPU path until diarization; the LLM clients kept reqwest's default redirect policy; the Vulkan suite forced the CPU so it would pass on the CI runner; the profile tree hard-linked the manifest along with the weights; the picker sent the response's field names; Start sent `mode = raw` from the first screen that had a button; the first-run download was a hook waiting for a method that had since landed; the rail's `analyze: true` predated `[meetings.analysis] auto`; and the install test passed a relative models path into a symlink under another directory. The alternatives on the table were to document each behaviour as intended, which the review had already read and rejected, or to fix the fallback and keep the decision.

## Decision

- **A broken file keeps the values in force.** `config::Loaded::retaining` installs the last valid configuration and sources beside the new text and its finding when a reload fails to parse or validate, so `system.health.ok = false` and `config.validate` report the file while `peer_token`, the retention and every other explicit value stay as they were. A file that is broken when the daemon starts stops the start, naming the key and line and never the value; a missing file is still the defaults. Every writer that derives its change from the file (the rules, the app mappings, the trusted endpoints, the QA seed) reads the values from the file text under the edit lock through `edit_values`, and the watcher's reload takes the same lock, so two additions keep each other's entry, an update cannot restore a deleted rule and a stale file is never installed over a write in flight. `validate` carries the cross-field and range checks the pipelines apply later (the transcribe chunk holds its overlap and margin, the live window its overlap and one positive tick, the silence floors and diarization shares are unit values, the clustering threshold a finite number of 0 or more), so a file, a `config.set` and a reload refuse the same values by key. This amends ADR 0009's recovery behaviour, which ran the daemon on the defaults. Closes daemon F3, F4 and F15.
- **A host file is merged, never replaced.** `dettivo mcp config` lifts an inline `mcp_servers = {...}` table to a regular one before adding the entry and refuses a value of any other kind by name; only `NotFound` reads as an empty file, any other read failure is reported with the file untouched, and the merged text lands through a rename. Closes agent-surfaces F11.
- **Verification names every file, and no engine loads what did not verify.** A verified manifest records each final file of a set (extracted members included) with the checksum it hashed to and the size and modification time it had then; readiness is `ready` only while the catalogue still names those checksums and the files still carry that identity, so a catalogue that changes one checksum, a file replaced in place, or a manifest written before the identities existed is `unverified` and hashed again before it counts. Every catalogue-backed load passes one gate (`dettivod::verify`): a `ready` model loads, an `unverified` one is hashed first (one hash at a time), a quarantined or missing one is refused by name with its download command; the start-up preload runs after the start-up verification rather than beside it. A private sideload is not a catalogue model and passes as before. This amends ADR 0005's verification, which was advisory. Closes engines F7 and F8.
- **The backend reported is the backend initialised, and `vulkan` never means CPU.** `backend::choose` answers a refusal under `backend_preference = vulkan` when the build has no Vulkan backend or no ICD is installed; `auto` keeps its fallback with the reason. Whisper asks ggml how many Vulkan devices enumerate before it loads with `use_gpu` (an ICD file alone is no device), Parakeet treats a `cpu` device under the strict preference as a refusal, the language engine names the preference in its refusal. The LLM CLI suite takes its backend from `DETTIVO_TEST_BACKEND`, so `test-llm-vulkan` runs on Vulkan and asserts `backend = vulkan` while the default suite pins the CPU; a generation that outlives its timeout and ignores the cancel terminates the engine process. This amends ADR 0004's CPU fallback, which the strict preference had inherited. Closes engines F10 and F14.
- **The tier leaves the CPU-only engines out.** `tier::detect` skips the engines in `CPU_ONLY` (the diarization engine, sherpa-onnx on the CPU by design) in the fallback check and in the list of engines on Vulkan, so a GPU machine reports the same tier before, during and after a speaker pass. This amends ADR 0029's tier rule, which downgraded on any resident engine on the CPU. Closes engines F13.
- **A redirect is a failure, and the request carries the policy's model.** The Ollama and OpenAI-compatible clients follow no redirect: a 3xx from the endpoint that passed the trust gate fails the request, and the transcript never reaches a host nobody confirmed; a deployment that redirected names its final URL in `endpoint_url`. A custom preset's `model` binds the provider before the request is sent, so the request names the model the policy hash describes; the local engine is bound to `[llm] model`, keeps it, and the policy is set back to that model so the two never disagree. This amends ADR 0023's trust gate and its policy resolution. Closes dictation F9 and F16.
- **A profile shares the weights alone and resolves a new tree through its ancestors.** `profile_models::ModelTree` hard-links the weight files and copies the manifest, a partial download and its sidecar, so a daemon under test can rewrite or truncate them without the real directory changing. The guard resolves a tree that does not exist yet through its deepest existing ancestor, so a parent that is a symlink into the real directory is refused before anything is created while a symlinked store elsewhere stays usable; a path that cannot be resolved is refused. This amends ADR 0043's hard-linked tree. Closes qa-rig F2 and F3.
- **The meeting screens send the contract's request.** The engine picker sends `speech.selection.set { provider, meeting_model }` and keeps the daemon's selection (`m_daemonProvider`) apart from the provider it offers when the daemon is on Parakeet, so picking the offered provider changes the daemon's selection instead of writing a meeting model alone; the daemon's answer reloads the picker before a start. The rail's analysis toggle starts on `[meetings.analysis] auto` and follows a configuration change while the rail is open; `analyze` and `diarize` go on `meetings.start` only once the user changed them (`MeetingLiveModel::start` takes them as `QVariant`, a non-bool is left out), so an untouched rail runs on the configuration the footer names. This amends ADR 0038's rail, whose analysis choice was always sent. Closes qt-hosts F5 and qml F5.
- **A start without `mode` and `language` runs the configured ones.** `dictation.start` no longer requires them on Linux: a field left out means `[dictation] mode` and `[dictation] language`, the values the hotkey path uses, and a value sent still wins for that session; registered in `docs/api/linux-deltas.md` with its fixture. Home's Start sends neither, so the mode the strip shows is the mode that starts. Closes qt-hosts F6.
- **First run downloads the local model the way Settings does.** `FirstRunModels` reads `llm.models.status`, asks `llm.models.download { model }` for `[llm] model` when it is not on disk, keeps a refusal on the row, follows the `model.download` events to `ready`, and recomputes the local row when the capabilities arrive after the providers. This amends ADR 0024's hook. Closes qt-hosts F7.
- **The install test resolves `--models` once.** `install-test.sh` resolves the directory to an absolute path when it parses the option and refuses one that does not exist by name, so the symlink under the daemon's data directory reaches the models the workflow's `.ci-data/dettivo/models` names. This amends ADR 0034's install test. Closes ops-and-record F4.

## Consequences

- A `config.toml` that is broken at start is a failed start with the key and line in the journal, where it used to be a daemon on the defaults; `dettivo config validate` names the same line. An edit that breaks the file while the daemon runs changes nothing until it parses again. Existing files that set `transcribe.chunk_seconds` at or under the overlap plus the margin, a live window smaller than its overlap plus a tick, a share outside 0 to 1 or a non-finite threshold are refused where they used to fail later in the pipeline.
- Every existing verified manifest is re-verified once, since it carries no file identities; with `verify_on_start` on that is the start-up hash, off it is the first load's. A manually provisioned model waits for its hash on first use.
- `backend_preference = "vulkan"` on a machine without a usable device is `load_failed` with the reason, where it used to be a CPU load reported as Vulkan; `auto` behaves as before. `just test-llm-vulkan` needs a Vulkan device and fails where the CPU used to pass for it.
- A benchmark or pack that ran the speaker pass on a GPU machine now records the GPU tier throughout; earlier reports that caught a CPU tier during diarization are not comparable to the new ones.
- A meeting started from the rail with nothing touched carries no `analyze` and no `diarize`, so the daemon's `[meetings.analysis] auto` and `[meetings.diarization] auto` decide; the rail's request is otherwise unchanged. `dictation.start` from an older client that sends `mode` behaves as before.
- Profile trees copy the manifest and any partial download (kilobytes) and still link the weights; the real directory stays read-only under every QA run, checked by a listing before and after.
- A packaging change that calls `install-test.sh --models` with a directory that does not exist now exits 2 naming it, where the smokes used to skip one by one.
